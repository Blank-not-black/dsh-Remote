# 通知、后台与峰谷提醒

[首页](README.md) · [日常操作](operations.md)

本页主要针对 Android。手机 Web 不能假装具备 Android 原生桥；HarmonyOS 有独立代理提醒/长时任务实现，能力和系统限制不同。

## KB-NOTIFY-01：前台正常，息屏后无通知或掉线

**先看：** “更多 → 通知与后台”中的后台轮询、审批/提问开关、服务状态；Android 系统通知许可与通知渠道、厂商电池策略、网络及配对状态。只读检查，不直接改变省电策略。

**判断：** 已允许通知不等于后台服务运行；前台收到了事件不等于息屏后系统继续调度。Doze、厂商省电与前台服务时限都会影响投递，不能承诺永久连接。

**下一步：** 使用本地操作日志的后台快照核对最后成功时间与失败类别。请用户比较前台/息屏、相同网络下的表现，再决定是否调整系统设置；不要因一次延迟就改云端或重装服务。

**验收：** 在用户授权的可控任务中，原问题条件下收到一次通知；请求处理后不重复提醒，点击进入正确主机与会话。通知验证涉及创建任务/审批时，事先说明影响。

## KB-NOTIFY-02：峰谷状态未知、提醒未送达或重复

**先看：** 主机 `dsh-cost-meter` 是否提供提醒规则、插件提醒是否启用、手机开关与系统许可、时间表是否新鲜。

**判断：** 规则由费用插件拥有，Remote Android 是接收与投递端。它每约 5 分钟同步时间表、每约 30 秒核对有效缓存；过期/插件不可用时停用，短时断网不意味着立即删除有效缓存。不能在手机端自建固定峰谷时刻替代上游规则。

**下一步：** 在 DSH 费用设置核对时间窗、提前量、提醒方向与生效日期，再核对手机缓存时间与当前连接。切主机/凭据后旧来源不应继续投递。

**验收：** 受控变化点只投递一次，内容时间与费用插件一致；重启去重、有效期和限时补发符合规则。界面显示状态或 JVM 策略测试通过，不能代替 Android 真机通知验收。

**其他平台：** HarmonyOS 的代理提醒/长时任务可能被系统拒绝或取消，进程内回退无法保证冻结后执行。相关目录内规则与工程文档优先，不能照抄 Android 设置路径。

依据：`packages/plugin/peak-reminders.mjs`、Android `PeakReminderService` / `PeakReminderPolicy` / `RemotePollService`，以及仓库 `docs/peak-reminders-and-issue18.md`。
