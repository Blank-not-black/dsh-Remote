# 回到最新与弱网流式精简（2026-10-17）

本轮修正流式输出期间「回到最新」的判定，并新增「弱网时关闭流式输出」。版本保持 `0.8.0-rc.3`；改动未提交，构建与实装见文末。

## 一、回到最新的问题

旧逻辑用 `reading` 标记判断按钮是否出现，而这个标记由 `pointerdown`、滚轮、触摸和滚动共同设置，只在 1.2 秒意图窗口内才会清除。用隔离会话实测（18 条历史 + 流式思考）得到：

| 场景 | 旧行为 |
| --- | --- |
| 在底部轻点卡片 | `reading` 被置真，按钮出现并显示「有新内容」，但下方并没有新内容 |
| 拖动滚动条/惯性滚动回到底部 | 滚动事件不在意图窗口内，`reading` 不清除，按钮留在底部且显示「有新内容」 |
| 上翻时新消息到达 | 按钮显示未读数，但到回底部后不会自动补齐流式内容 |
| 流式内容增长 | 只要 `reading` 为真，`liveHtml` 冻结；底部用户会看到停止更新的思考块 |

## 二、修改

- `history.js` 新增 `atBottom`（距底部 ≤24px 的实时位置，不再依赖意图标记）。
- `onScroll` 改为位置优先：到达底部立即清除 `reading` 并同步待显示内容、跟随到底；向上滚动仍在意图窗口内锁定阅读位置。
- `pointerdown` 仅在确实离开底部时锁定阅读；在底部轻点不再暂停跟随。
- `set()` 在下一次数据更新时丢弃「已在底部」的陈旧 `reading`，但只在手势结束（超过 1.2s 无滚动意图）后清理：从底部开始上翻时，流式增量不会再把视图拉回底部。
- 滚动到底触发窗口扩展时，如果本来就在底部，直接跟随到底，不再用锚点把用户留在底部上方。
- 按钮显示条件改为 `atBottom && unread===0 && !tailEvicted` 时隐藏；文案仍是未读数或「有新内容」。
- 移动端与桌面端共用同一套 `HistoryView`，只改两处 `changed` 回调。

## 三、弱网时关闭流式输出

设置入口：「更多 → 外观与输入 → 对话与输入 → 弱网时关闭流式输出」，网络模式下方，默认开启。存储键 `dshWeakStreamOff`（`'0'` 关闭），清空本地数据时一并移除。

生效条件：`DshNetwork.profile().weak`（网络模式为弱网，或自动判断检测到 saveData/2g/3g/高 RTT/低带宽/实测延迟 ≥800ms）。

开启后：

- 不渲染流式思考块（`partialReasoningHtml()` 直接返回空），未完成的思考不会占用视口；
- `renderHistory` 过滤掉尚未返回的 `tool/call`，只保留已完成并配对结果的工具活动；结果到达后该行立即出现，状态为「已返回」；
- 已完成的消息、工具结果、审批/提问卡片不受影响；
- 切换开关或网络模式立即重绘（`window.applyStreamPreference`），无需刷新。

限制：只影响显示，不丢弃事件；上翻期间到达的完成事件仍会累计未读。自动判断依赖浏览器的 Network Information API 或实测延迟，浏览器不支持时请手动选「弱网优先」。

- 隔离浏览器实测（`dist/stream-2026-10-17/`，模拟主机与流式事件）：

| 场景 | 结果 |
| --- | --- |
| 底部收到新消息 | 按钮隐藏，无「有新内容」 |
| 上翻后新消息到达 | 按钮显示「回到最新 (1)」 |

| 弱网精简开启 | 思考块消失，运行中的 `run_tests` 不显示 |
| 运行结果返回 | `run_tests` 以「已返回」出现 |
| 关闭该设置并回到会话 | 思考块恢复显示 |
