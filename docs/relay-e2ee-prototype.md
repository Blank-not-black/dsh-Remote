# 中转端到端加密：协议设计与隔离原型

2026-11-01。状态：**隔离原型通过，未接入产品、未部署**。当前线上赞助中转仍是两段 TLS 在云端终止，不能据此把预公告改成“已支持端到端加密”。

## 目标与信任边界

目标是让手机与用户主机成为解密端点。即使中转进程、其 HTTPS 证书或云端管理员失陷，也不能直接读取对话、历史、审批、图片和 Remote 访问凭证，或在不被发现的情况下修改、重放传输记录。

仍信任用户主机、已安装的客户端、操作系统和首次配对过程。加密不保护已被控制的终端，也不隐藏中转授权、目标租户、连接时间、流量大小、IP 等元数据；中转仍可拒绝或中断服务。主动用户仍可经 DSH 对话读取文本和工具输出，文件接口限制不构成数据防泄漏保证。

## 原型采用标准 TLS 1.3 内层通道

```text
可信客户端：HTTP / WS → TLS 1.3 加密
                    ↓
外层 HTTPS Upgrade → 云端仅转发内层 TLS 字节 → 主机 TLS 1.3 解密
                                                    ↓
                                         身份验证、套餐限制、Remote / DSH
```

采用 RFC 8446 的系统实现，不自行设计 ECDH/HKDF/AES 消息协议。Node 内置 `tls` 可在现有 Duplex 上建立内层 TLS；外层 HTTPS 继续保护连接与路由。原型强制 TLS 1.3、完整握手，协商 HTTP/1.1，不传入会话恢复票据、不发送 0-RTT 数据，不降级或自动换用旧链路。

`experiments/relay-e2ee/tls-channel.cjs` 只提供两项实验 API：

- `createPairing(certificate, hostname)`：将**可信本地来源**的主机证书转换为配对记录，包含协议标识、主机名、证书和 SHA-256 DER 指纹。只含公开信息，不含私钥或 Remote 令牌。
- `connectPinned({socket, pairing, timeoutMs})`：在已经建立的外层通道上进行内层握手，同时检查证书链、有效期、主机名、精确证书指纹和 TLS 版本。成功后才交出可写应用数据的流；失败和超时销毁内外通道，不替换证书、不重试写入。

主机身份固定使用独立的证书，与云端 HTTPS 证书、赞助密钥和现有主机 Ed25519 中转接入密钥分开。证书轮换需要通过原可信主机授权，或重新本地配对；不能接受云端响应自动更新。具体主机证书生成、密钥保护、吊销和轮换尚未实现。

## 首次配对与认证

1. 用户在自己的主机本地打开管理页面，通过系统能力生成主机证书与私钥。私钥仅存在主机的私有状态目录，Windows 使用 ACL，其他平台使用受限文件权限；不进入工作区、二维码、云端、日志或备份共享目录。
2. 本地页面提供含协议版本、稳定主机身份和证书的二维码/配对文件。手机使用包内客户端读取，确认并保存。原型用测试代码直接传入证书模拟此可信步骤，**尚未实现二维码和设备存储**。
3. 手机先建立外层租户通道，在发送 Remote 访问令牌前完成内层身份校验。Remote 令牌仅出现在内层 HTTP；外层的路由授权只能授予受限中转能力，不能替代主机访问认证。
4. 换主机、证书改变、证书过期或配对丢失时明确中止并引导重新配对。不能“忽略证书错误”，不能静默信任新指纹。

用户必须确认配对来源。由同一个不可信中转返回的证书和指纹即使互相匹配，也不能建立可信身份。

## 与当前产品的接入差异

| 部位 | 原型已验证 | 正式接入前必须完成 |
| --- | --- | --- |
| 客户端 | Node `tls` 在外层 HTTPS Upgrade 上建立内层 TLS | Android 使用系统 TLS/原生传输桥接，核对系统 TLS 1.3 可用版本及域名验证；鸿蒙另行验证系统 SDK。均未实现 |
| 普通浏览器 | 没有原生 API 将 `fetch` / WebSocket 直接替换为内层 TLS 流 | 暂不宣称支持。需独立选择可信客户端分发及成熟协议方案；不能以手写 TLS 或新创加密协议绕过零依赖约束 |
| 云端 broker | 测试夹具在外层解密后仅转发内层字节 | 当前 broker 会解析 HTTP，尚未添加新的 opaque 通道、租户路由和并发限制；新路由应固定租户后端，不能允许任意目标代理 |
| 网关 | 测试主机在内层解密后验证访问令牌，并执行现有文件路径策略 | 真实网关的 TLS 端点、回环代理、HTTP/WS/轮询全路径，以及完整主机鉴权仍需接入 |
| 套餐限制 | 主机夹具拒绝文件下载；图片可通过 | 现有 `basicBody`、图片魔数/大小校验、WS 白名单与全部文件/导出限制必须迁到专属主机入口，并取得可验证的云端授权规则，不能由请求字段自报套餐。拒绝规则缺失/过期；不能阻断原有局域网入口 |
| 月额度与撤销 | 未修改 | 云端按内层密文字节计量和持久化，包含加密开销；到期/撤销/超额需断开 opaque 通道。需更新用户流量口径并回归并发、异常退出和月界线 |
| 更新与供应链 | 原型代码由本地 Node 加载 | APK/客户端使用本地签名包内代码，不从中转加载远程脚本。经同一中转下载的网页若可被替换，即使采用 Web Crypto 也不能抵御恶意脚本窃取明文 |

零新增依赖和单文件网关发布形态保持不变。实验文件不进入 `embed-relay`、插件包或 `public/`，无需修改网关或同步产物。正式接入才扩展嵌入与同步流程。

## 恢复、重放与消息语义

- TLS 1.3 对每条记录提供认证加密与隐式序号。修改、重复同一记录或将旧连接的记录注入新连接会被拒绝；重连进行完整握手并产生新的密钥。
- 此性质不能代替业务幂等。同一用户可以在新的合法连接中再次提交相同请求；应用仍须沿用稳定操作 ID 和现有 `operations` 回执，执行后丢回执时显示结果不确定，通过 GET 查询，不自动重发 POST。
- 内层 WS 沿用 downlink-only，不增加应用心跳。底层故障、配额用尽等关闭后，应用可以按既有退避恢复连接，但写入不由传输层重试。
- 主机解密后的回环段只允许同机 Remote，不开放任意地址或端口转发。云端保留元数据计量和最小路由鉴权，不能持有主机 TLS 私钥。

## 验证与复现

```powershell
node --test tests/relay-e2ee.test.js
npm run check
```

13 项原型测试全部使用 `127.0.0.1` 随机端口、公开测试证书与固定夹具令牌，不读取真实 `~/.dsh-remote`、不请求生产服务、不创建真实资格。测试结束销毁套接字并关闭监听器。

覆盖实际 TLS-in-HTTPS 的 HTTP、流式轮询、图片和 WebSocket 下行；对外层解密后的字节取样，确认不出现测试令牌、接口路径和正文。取样只是附加回归断言，保密性依据是标准 TLS，而非字符串搜索。

恶意证书测试使用由**同一个受信任测试 CA 签发且 SAN 为 localhost**的另一证书，确保实际触发精确证书 pin 校验，而非仅被 CA/主机名检查提前拒绝。另覆盖修改配对指纹、TLS 1.2 降级、密文篡改、连接内重放、跨连接重放、新连接密钥不同、握手超时、明文后端、关闭的流、断线前未执行和执行后回执丢失两种场景。回执丢失不触发重发。

`tests/fixtures/e2ee-impostor-{cert,key}.pem` 与既有 `relay-test-{cert,key}.pem` 均为公开的测试材料，绝不能部署。新假冒证书由既有测试 CA 签发；OpenSSL 仅用于一次性生成提交的测试夹具，运行测试不依赖 OpenSSL 或任何第三方库。

尚未验证 Android/鸿蒙原生桥接、浏览器、实际 broker/网关接入、真实证书生命周期、内层大文件与背压压力、云端额度/撤销或真机切网。原型并非完整端到端加密产品，也没有经过独立密码协议/实现审查。

本轮最终全量 `npm run check`：1195 项，1175 通过、20 跳过、0 失败；原型专项 13/13。日志保存在忽略目录 `dist/relay-e2ee-20261101/`。最初限权运行的两项既有 supervisor 测试无法读取进程身份，允许进程查询后通过。公开假冒私钥夹具初次由 Cygwin OpenSSL 生成的 Windows ACL 阻止另一执行身份读取，已重建为普通仓库测试文件，并在两种执行环境复验专项通过。

另一次全量及随后的插件事务独立复验，分别观察到未改动的 `accepted batch finishes in a real detached worker after the manager is recreated` 用例在临时锁文件读取时 ENOENT、临时回执替换时 EPERM；随后最终全量通过。原始日志保留，未修改该模块或断言，也未宣称这些并发文件访问问题已修复。

## 发布前置与公告口径

先完成原生客户端能力评估和上述产品适配，再做隔离全链路、恶意云端、限额撤销与手机真机验收。保留明确的连接安全状态，让用户区分当前 TLS 中转和已验证主机身份的端到端链路；安全连接失败时不回退旧协议。

目前公告可使用：“我们正在验证手机与主机之间的端到端加密方案，现有试运营中转仍采用两段 TLS 加密，后续进展另行说明。”不得使用“运营者无法读取内容”作为已上线承诺。赞助申请表单与付款截图属于提交给运营者的信息，不属于本端到端通道保护范围。
