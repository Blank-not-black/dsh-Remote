# 技能中心前端排版调整

日期：2026-10-14。版本：0.7.5-rc.4。

用户反馈技能中心直角突兀、换行不自然。本轮采用 [Anthropic frontend-design](https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md) 的布局、文字层级、选择器隔离与截图复核流程，并参考已安装的 design-everyday-things、cognitive-psychology-ux。前端 skill 本轮读取官方源文件使用，没有新增 Remote 依赖。

## 设计与取舍

技能中心的主要任务是寻找和阅读已安装主机提供的技能。保留原来的安静阅读风格和五套主题，不增加装饰性首屏。设计规则：

| 项目 | 本轮选择 |
| --- | --- |
| 颜色 | 继续使用 `--dsr-*`：亮色基底 #F5F7F8、表面 #FFFFFF、边框 #C7D2D8、重点 #176B87；深色基底 #0D1117、表面 #161B22，其余主题仍使用现有变量 |
| 字体 | 延用应用界面字体；页面标题21–22px，技能名称17–18px，正文14px，元信息12–13px；纯文本正文用系统等宽字体 |
| 形状 | 搜索/筛选/工具按钮12px圆角，技能容器18px，正文区域14px；统一点击高度，保留清楚的层级 |
| 布局 | 搜索优先占一行；手机来源/状态、排序/刷新两两成行；宽面板可合并；控件按实际容器宽度响应 |
| 换行 | 按自然词界断行，超长连续字符串才折行；中文标点采用严格断行；按钮和状态保持完整短语 |

排除了两种不适合本次任务的方向：用更多大卡片承载每个筛选会增大阅读前的滚动量；强制所有筛选在手机同一行会再次截断文字。采用统一圆角的紧凑筛选区，卡片只承担技能内容。

## 实际问题与修改

- 原搜索框只有21.43px高、0px圆角、浏览器默认 inset 边框；三个 select 也没有组件样式。统一控件边框、颜色、字体、46px高度和12px圆角。
- 原手机四个控件同排，来源/状态选择器仅约93px宽，完整状态标签被裁切。现在手机两列，DOM键盘顺序与视觉顺序相同。
- 原标题/说明通用 `overflow-wrap:anywhere`；改用自然断行和超长单词回退，整理正文与标题行高。没有改写主机技能正文中的换行。
- 原宽窗口内窄内容区可能把刷新按钮压到26px；加入容器查询和按钮最小宽度，确保根据可用空间调整。
- 正文搜索、阅读模式和复制工具也采用响应布局；代码块和 Markdown 表格在自身区域滚动，避免撑宽整页。
- 专属页返回按钮与主机提示保持完整短语，长主机名用省略号处理。

## 验证

检查实际 App WebView 的320、360、390、412、620、768、1024、1360px视口，以及320/412px详情：控件至少44px、圆角非0，控件内容与页面均无横向溢出。这个宽视口检查包含手机页面在宽窗口内的窄内容区；另行检查桌面页面源码在隔离 iframe 的布局。

design-everyday-things五项工程走查采用0/1/2分：调整前8/10，发现可操作性和布局映射受控件高度、文字截断影响；调整后10/10。可发现性2、结果反馈2、错误恢复2、控件映射2、无效选项约束2。该评分是工程走查，不是用户研究结果或视觉审美的量化证明。
