# 可选插件产品逻辑复核

日期：2026-10-14。范围：Remote 手机 WebUI、Android WebView、桌面 WebUI 的可选插件入口与阅读流程。

## 产品约束与反馈依据

Remote 的主要任务是远程查看和操作用户已有的 DSH 主机。适配插件意味着识别主机已经提供的能力，并为使用者提供合适的界面。插件选择属于用户；专属页面应从对应已安装插件或会话任务进入。

本轮依据是用户在本次对话中的直接反馈：默认把技能、费用等放在入口会让可选适配像必备功能；查看技能、查看执行中的历史曾被更新抢走位置。没有额外受访者、量化转化数据或完成率，以下结论是产品规则和工程走查。

## 四个 skill 的应用

| Skill | 采用的方法 | 本轮落点 |
| --- | --- | --- |
| product-manager-toolkit | 先明确问题、产品边界与验收标准，再确定优先级 | 先纠正默认入口和可选依赖关系，保留已经实现的阅读能力 |
| ux-researcher-designer | 用户反馈→任务路径→可观察的验证场景 | 分别验证无插件、单插件、多个插件；区分真实主机与模拟状态 |
| design-everyday-things | 概念模型、操作映射、状态反馈、约束 | 入口放在对应插件卡片；未知能力隐藏；无法读取时给出返回和重试路径 |
| cognitive-psychology-ux | 渐进呈现、减少无关选择、保护注意力与记忆 | 取消默认扩展推荐卡片；专属页面返回保留筛选和位置；历史阅读不随实时更新跳走 |

以上 skill 安装在开发者的 Codex 技能目录，未作为 Remote 的运行时依赖或内置插件。

## 实施后的规则

1. “插件”默认打开当前主机的插件管理列表，不再展示技能、费用的默认功能卡片，也不设置全局技能中心标签。
2. 只有插件包名完全匹配、配置启用、运行时确认处于 active，才在该插件卡片上显示阅读入口。配置停用、未安装、启动失败、等待依赖和未知运行时均隐藏入口。
3. 会话中的洞察按钮根据可用能力呈现“上下文分析”“费用与额度”或“上下文与费用”；缺少的能力不显示标签。能力探测只读取插件状态，余额和技能内容在用户主动打开后读取。
4. 技能与费用保留专属页面。从页面返回插件列表保留筛选、展开状态与滚动位置；离开列表时暂停其轮询。
5. 完整上下文在当前会话的对话框内展开，不切换到插件管理页。返回时恢复历史阅读位置；期间缓存实时历史更新，继续遵守既有阅读保护。
6. 状态缓存最多复用 15 秒；连接或认证变化时失效。失联后的探测返回未知，不使用过期能力继续推介功能。迟到的旧连接响应不能恢复入口。
7. 插件添加仍由用户在“添加插件”中主动选择。本轮不安装、卸载、内置任何 DSH 可选插件。
8. 手机插件卡片中的阅读入口单独占一行，管理动作保持横向文字和足够的点击高度，避免新增入口挤压“详情/更新/卸载”。

## 工程走查

依照 design-everyday-things 的五项诊断问题，采用 0=未满足、1=部分满足、2=实现明确的本轮走查尺度。这是工程判断，不是用户研究评分。

| 问题 | 结果 | 依据 |
| --- | --- | --- |
| 用户能判断该做什么吗？ | 2 | 对应插件卡片提供具名动作；上下文动作归属当前会话 |
| 用户能理解发生了什么吗？ | 2 | 保留加载、失败、配置状态、任务阶段和日志反馈 |
| 用户能从错误恢复吗？ | 2 | 阅读失败可刷新或返回列表；连接变化拒绝旧响应 |
| 控件与输出的关系清楚吗？ | 2 | 技能对应技能页，费用对应费用页，会话上下文对应当前会话 |
| 无关或不可用选项被隐藏吗？ | 2 | 无可用插件时没有推荐卡片或洞察按钮；单一能力只有对应标签 |

## 验收场景与证据边界

| 场景 | 可观察结果 |
| --- | --- |
| 无适配插件 | 普通插件列表，无适配入口和洞察按钮，不请求技能或余额 |
| 仅一个适配插件 | 只有该插件卡片上的动作；单一洞察标签不访问另一个能力 |
| 多个适配插件 | 各插件入口独立，默认页仍是插件列表 |
| 停用/失败/未知运行时 | 状态刷新后隐藏入口；不通过包名猜测可用性 |
| 更换主机或认证 | 清除能力缓存，旧请求不能污染新主机 |
| 技能页返回 | 列表筛选、展开状态和滚动位置保持 |
| 完整上下文返回 | 保留会话身份和历史阅读位置 |
| 执行期间读历史 | 连续实时更新不抢走位置，用户可主动回到最新 |

自动测试与本地模拟器证据见 `dist/optional-plugins-0.7.5-rc.3/REPORT.md`。无插件/单插件场景通过隔离的 UI 状态验证，未为了测试改动真实主机的可选插件配置。真实手机与 HarmonyOS 本轮不作为已验证范围。后续可让真实使用者完成“找到已装技能→阅读→返回”和“执行时回看历史”两项任务，记录首次点击、误操作及中断；本轮不虚构这些结果。
