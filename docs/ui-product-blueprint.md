# DSH Remote 四端产品与 UI 低保真蓝图

> 目标：把 DSH Remote 从“数据展示页”重构为“远程工作状态控制台”。
>
> 本文先定义产品角色、使用动线、信息优先级和视觉语言，不涉及具体代码实现。

## 1. 产品定位

DSH Remote 面向的是正在使用 DSH 的开发者或操作者。用户打开它，不是为了阅读一堆指标，而是为了快速确认：

1. 系统现在能不能用；
2. 有没有需要处理的事情；
3. 最近正在进行什么工作；
4. 下一步应该采取什么动作。

产品主张：

> 一眼确认，一步操作，深入管理。

## 2. 四端角色

| 端 | 产品角色 | 首要任务 | 不应该承担的内容 |
| --- | --- | --- | --- |
| 手机 App | 远程工作入口 | 看状态、处理会话、传文件 | 复杂诊断、完整运维数据 |
| 桌面端 | 完整工作台 | 持续工作、查看上下文、管理会话 | 把所有统计指标铺满首页 |
| 网关控制台 | 系统运维中心 | 管理设备、连接、Token 和诊断 | 面向普通用户的操作引导 |
| DSH 插件端 | 快速入口与本地控制器 | 确认状态、启动服务、打开控制台 | 复制完整控制台和复杂图表 |

插件端与控制台共享状态，但不共享完整页面。插件负责“现在怎么样、下一步做什么”，控制台负责“为什么、怎么深入管理”。

## 3. 统一状态模型

所有端只围绕五种用户可理解的状态组织界面：

| 状态 | 用户看到的结论 | 主动作 |
| --- | --- | --- |
| 未绑定 | 尚未连接工作区 | 绑定工作区 |
| 正常运行 | 系统运行正常 | 打开最近工作 |
| 需要关注 | 有事项需要处理 | 查看待处理事项 |
| 已离线 | 网关或上游不可达 | 重新连接 / 查看诊断 |
| 正在更新 | 服务正在更新中 | 查看进度 |

状态变化时，主按钮、页面标题和首页内容一起变化。不能只改变一个颜色或增加一个小红点。

## 4. 手机 App：首页控制中心

首页不再是“版本 + 4/4 + 多张统计卡片”，而是一个状态驱动的控制中心。

```text
┌──────────────────────────────┐
│ DSH Remote        工作区 · 状态 │  ← 当前上下文
├──────────────────────────────┤
│                              │
│       系统运行正常             │  ← 唯一主焦点
│   4 个通道在线 · 12 秒前同步    │
│                              │
│       [ 继续最近会话 ]          │  ← 唯一主动作
├──────────────────────────────┤
│ 需要你处理                     │
│  ┌──────────────────────────┐  │
│  │ 等待审批 · 1 项        › │  │
│  └──────────────────────────┘  │
├──────────────────────────────┤
│ 最近工作                       │
│  会话名称             刚刚     │
│  文件传输             3 分钟前  │
├──────────────────────────────┤
│ 系统详情                       │
│  DSH 版本 · 网关 · 连接模式     │  ← 次级信息，可展开
└──────────────────────────────┘
        会话  文件  ◉主页  统计  设置
```

首页的优先级固定为：

> 状态结论 → 待处理事项 → 最近工作 → 技术详情。

离线时，首页主焦点直接变成“网关已离线”和“重新连接”，不再展示大量没有意义的空卡片。

## 5. 底部导航

五个入口的产品职责明确：

- 会话：最常用的工作入口；
- 文件：远程文件操作；
- 主页：系统控制中心；
- 统计：历史趋势和成本；
- 设置：连接、外观和维护。

主页位于中央，采用圆形控制舱作为品牌焦点。底部整体可以使用平滑曲线承托中央控制舱，但曲线只作为导航结构，不延伸到其他页面造成装饰噪音。

中央主页的状态光环只在状态发生变化时动作，正常状态保持稳定，不持续闪烁。

## 6. 桌面端：完整工作台

桌面端不做成手机页面的横向放大版，而采用“左导航、中工作区、右上下文”的三段式工作台：

```text
┌──────────────┬────────────────────────┬──────────────────┐
│ 工作区 / 会话 │ 当前工作区              │ 上下文详情       │
│              │                        │                  │
│ 新建会话      │ 当前会话 / 文件任务      │ 会话信息         │
│ 最近会话      │ 待处理事项              │ 文件信息         │
│ 收藏会话      │ 最近活动                │ 连接详情         │
│              │                        │ 操作记录         │
└──────────────┴────────────────────────┴──────────────────┘
```

中间区域只服务于当前任务。右侧面板按需出现，不主动抢占主空间。

## 7. 网关控制台：运维中心

网关控制台面向维护者，信息顺序是：

> 运行状态 → 快捷操作 → 连接设备 → 请求与 Token → 诊断配置。

首屏应该先给出一个运行结论：

```text
网关运行正常
DSH 上游正常 · 1 台设备在线 · 已运行 2 小时 18 分钟

[重启网关] [复制令牌] [打开诊断]
```

版本、IP、端口等技术资料进入“运行详情”，不再与状态结论使用同样大的卡片。

桌面控制台强调设备和诊断；移动控制台强调状态和快捷操作，二者使用同一套数据层级，但不是同一套排版。

## 8. DSH 插件端：快速入口与本地控制器

插件端是用户在 DSH 工作过程中顺手打开的面板，因此必须紧凑、明确、不打扰。

```text
┌──────────────────────────┐
│ DSH Remote        已连接  │
├──────────────────────────┤
│ 网关运行正常              │
│ 1 台设备在线 · 最近活动 12 秒前 │
│                          │
│       [ 打开控制台 ]       │  ← 唯一主动作
├──────────────────────────┤
│ [复制连接信息] [重启网关]  │
│ [查看更新]   [更多]        │
├──────────────────────────┤
│ 版本与支持                 │
└──────────────────────────┘
```

插件端按状态替换主动作：

- 未绑定：绑定工作区；
- 未运行：启动网关；
- 正常：打开控制台；
- 异常：查看诊断；
- 有更新：更新插件。

插件端不放完整 Token 图表、设备长表格和复杂日志。点击“打开控制台”后再进入完整管理页面。

赞赏、反馈、版本历史放到“更多 / 关于与支持”里，不与启动、绑定和打开控制台竞争注意力。

## 9. 统一设计语言

### 视觉层级

每个页面只允许有一个主焦点、一个主动作。其他内容必须通过字号、颜色、位置或容器层级降权。

### 色彩

不重新发明配色，沿用现有四套主题，并让它们共享同一套信息层级、组件语义和状态表达：

| 主题 | 既有色调 | 适合表达的气质 |
| --- | --- | --- |
| 默认深空 | 深蓝紫底、蓝色与紫色强调 | 安静、专业、技术感 |
| 落日 | 深钴蓝底、琥珀橙与米色强调 | DSH 品牌感、操作感、对比明确 |
| 易北爱乐厅 | 米白底、沙金与深沙色强调 | 克制、温和、质感 |
| 草原孤塔 | 鼠尾草与土色底、橄榄绿和陶土红强调 | 自然、中性、低饱和 |

四套主题不是四种不同的布局，而是同一产品语言的四种情绪。组件不能因为换主题就改变位置、优先级或交互方式。

主题使用规则：

- 背景色承载整体氛围，不承担状态含义；
- 主题主色用于品牌、主按钮和当前导航；
- `success / warning / error / info` 只用于状态，不被主题色替代；
- 主题的第二强调色用于辅助信息、图表和局部焦点，不用于制造多个主按钮；
- 同一页面最多一个高权重主色区域，避免再次出现“每张卡片都在发光”。

这意味着重构重点是“用已有四套色调重新组织内容”，而不是把所有端改成单一的中性灰或重新设计第五套配色。

### 形态

- 少用重复的圆角卡片；
- 混合使用大面积状态区域、分隔线、局部浮层和列表；
- 圆形只用于核心状态和中央导航；
- 图标统一使用线性 SVG，不使用 Emoji；
- 动效只反馈状态变化，不做持续装饰动画。

## 10. 第一轮重构范围

第一轮只做最能改变产品感受的部分：

1. 插件端状态面板和主动作；
2. 网关控制台首屏信息层级；
3. 手机 App 首页控制中心；
4. 底部导航中央控制舱；
5. 桌面端三段式工作台骨架。

统计详情、设置细节、日志、动画和装饰性优化放到第二轮。

验收标准不是“卡片是否更漂亮”，而是：

- 用户 3 秒内知道系统是否正常；
- 用户 5 秒内找到下一步动作；
- 插件端不会与控制台争夺功能；
- 首页不再被技术数据和空状态占满；
- 手机、桌面、控制台、插件拥有不同角色，但看起来属于同一个产品。
