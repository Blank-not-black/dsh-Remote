# 基础中转赞助试运营

本功能为可选的云端设施，默认关闭。本地构建、提交开发代码不会部署、收款或发送邮件。2026-11-01 已按用户指令在现有试运营控制域名部署并启用，详见[上线与入口清理记录](sponsor-live-2026-11-01.md)。

## 已确定的规则

- 单次微信赞助 **1 元及以上**，人工核验到账后开通一个月；更高金额不增加期限、额度或设备数，不开放多月预付。
- 一个月从审核通过时开始，按北京时间同日同时间至下个月；下个月没有该日期则取当月最后一天。界面及开通邮件显示具体到期时间。
- 每个服务月上传与下载合计 **5,000,000,000 字节**；使用独立 `monthly-quota.json`，不在午夜重置。统计包含隧道内 HTTP 头、正文及 WS 帧，不含 TLS/TCP 和控制握手开销，与云厂商账单不完全相同。
- 一个资格绑定一个网关公钥，无法同时或轮流绑定另一网关；续期保留原公钥和公网地址，轮换开通密钥。重装丢失私钥或换设备须联系运营者处理，首版没有自助换绑。
- 开放对话图片预览，计入额度；文件浏览、上传、下载、文件收件箱、会话文件下载及导出接口返回 `403 FILE_TRANSFER_NOT_ALLOWED`。本地 `/fs/file` 只放行 PNG/JPEG/GIF/WebP 图片读取，附件 RPC 只放行经过格式检查的图片结果，单图最大 12MiB，不接受范围读取。图片可被截图或保存，不承诺技术上阻止图片另存。
- 限制的是 Remote 的文件传输接口，不是内容审查或通用数据防泄漏；用户仍可在 DSH 对话中执行任务、查看文本和工具输出。
- 初期最多 **79** 个占用名额，包含有效授权、已提交待审核申请和仍在预留时间内的未付款草稿。79 是运营上限，并非已通过 79 人同时在线的容量测试。

## 申请与人工审核

用户访问中转控制域名的 `/sponsor/`：

1. 每天北京时间 09:00 至 22:50 前可获取申请编号，初始预留 90 分钟。22:50 起停止发放新编号，已有编号可在 23:00 前请求发码。23:00 后仍可验证尚未过期的码、提交已验证的申请和查询进度。以服务端时间为准。
2. 填写接收邮箱并发送验证码。运营端本机进程从云端待发队列取码，用现有邮箱发送。验证码 10 分钟有效，输错 5 次后需重发。验证成功后锁定邮箱，并确保编号自验证起至少还有 60 分钟。运营端离线时暂停发码和展示赞赏码。
3. 验证后用页面上的微信赞赏码赞助，备注申请编号，再填写金额和付款截图。截图支持 PNG/JPEG/WebP，最大 2MiB；申请人无需填写交易号。
4. 提交后保留名额等待人工审核；申请查询使用单独的随机凭证，保存在当前浏览器的 sessionStorage。可在“保存或恢复申请进度”私下复制凭证，换浏览器后粘贴恢复；凭证只经 Authorization 传输。持有该凭证可查询邮箱和验证进度，截图和中转密钥仍由审核端处理。

运营者打开同一控制域名的 `/sponsor/admin`，输入专用审核密钥：

1. 查看截图，在**自己的微信收款端**确认到账、金额、备注申请编号；不能只凭截图判断成功。
2. 在后台登记实际到账的微信交易编号，勾选核验确认后通过。申请人无需填写这个编号。同一交易编号只能对应一次开通，重复通过同一申请不会延长期限或另发授权。
3. 页面生成收件邮箱、邮件主题和包含密钥、到期时间、规则、新版 App 局域网自动配对步骤及配对日志反馈方式的正文。复制到自己的邮箱后人工发送；页面本身不访问邮箱、不自动发信。
4. 实际发出后点击“我已向该邮箱发送”。通过和发送为两个状态，断线后可重新读取同一份正文，不能因结果不明重新签发。
5. 未通过时填写原因及后续核对/退款处理方式。页面保存原因供申请人查询，运营者自行联系对方和处理退款；本设施不自动退款。
6. 管理列表支持按审核/发送/有效/到期/撤销状态筛选，以及申请编号、邮箱搜索，并显示邮箱验证状态。容量行显示验证码服务在线状态。有效资格显示到期时间、网关绑定状态和云端月额度/在线状态，流量读取失败会显示账本不可读。
7. 可在管理页暂停、恢复新申请，设置保存在 registry，重启后保留；不影响已有编号继续提交和待审核材料。环境变量 `DSH_RELAY_SPONSOR_ACCEPTING=0` 的紧急暂停优先，管理页不能覆盖。
8. 撤销有效资格需填写原因并再次勾选确认。云端拒绝新连接，并由既有 sweep 断开现有隧道；申请人能查询撤销说明。不会自动退款或发通知。旧申请不能撤销续期后的新资格，过期或撤销后不能再读取、标记发送旧交付信息。

客户端先在网关 `/relay` 或管理别名 `/admin/api/relay` 绑定运营者发出的密钥。启用加密中转的主机推荐使用 0.8.5 及以上 Android App：先连接主机局域网地址，再到「更多 → 主机与连接 → 云服务器中转」点击「通过当前局域网连接自动配对」，成功后自动添加公网地址并保留局域网连接。旧版 App、普通浏览器和鸿蒙不支持该入口；未启用加密中转的主机仍可按原来的公网地址和 Remote 访问令牌连接。配对失败时可在同一区域展开「配对日志（可复制反馈）」并发送给运营者，日志不含访问令牌、设备密钥或路由凭据。状态增加 `quotaPeriod`、`monthlyLimitBytes`、`fileTransfer`，在首条流量回报前也能说明月额度、单网关和文件限制；旧每日档保持原有行为。赞助入口会重新读取公开开关，区分暂停/满额与正常申请，暂停或满额时仍可前往查询已有申请。

同一邮箱有待审核或仍有效的资格时，不接受再次开通；到期后可以用同一邮箱重新申请。续期通过后仍需在原网关重新填写新的开通密钥，原私钥、公网地址与设备绑定保留。邮箱验证码确认该地址可以收信。退款或变更邮箱仍需另行核对付款证据。

付款后错过草稿期限、关闭会话丢失查询凭证或无法匹配到账时，保留付款截图与申请编号联系运营者人工处理；不要重复付款。已提交的付款申请不会自动超时释放名额，以免已付款者被静默挤出。运营者应及时审核，并明确约定审核时间与无法开通时的退款安排。

## 部署准备（用于新环境）

沿用 [中转部署文档](../relay/README.md) 中的回环 HTTP 入口、有效 HTTPS、专用控制域名及租户 DNS/证书。需要复制 `relay/*.cjs`、`relay/sponsor/` 及本次使用的赞助码 PNG；不增加依赖，也不改变网关单文件发布形态。随机租户域名必须预先配置通配 DNS 与匹配的证书，或另行安排对应域名；审核通过不会自动签发证书。

通过 systemd 的私有 EnvironmentFile 设置（文件应 0600，仅运行用户及管理员可读）：

```ini
DSH_RELAY_SPONSOR_ENABLED=1
DSH_RELAY_SPONSOR_ADMIN_TOKEN=<独立生成的至少32字符随机密钥>
DSH_RELAY_SPONSOR_MAX_USERS=79
DSH_RELAY_SPONSOR_ACCEPTING=1
DSH_RELAY_SPONSOR_HOURS=09:00-23:00
DSH_RELAY_TRUST_PROXY=0
DSH_RELAY_SPONSOR_QR=/opt/YOUR_SERVICE/donate.png
DSH_RELAY_SPONSOR_CONTACT_EMAIL=operator@example.com
```

`DSH_RELAY_SPONSOR_HOURS` 格式为 `HH:MM-HH:MM`，固定使用北京时间，停止发放编号的时间为关门前 10 分钟。`DSH_RELAY_SPONSOR_QR` 指向微信赞助码，未设置时默认读取仓库 `public/donate.png`。申请页使用带 Bearer 的 `GET /sponsor/api/applications/:id/qr` 读取图片，部署用的赞赏码文件应保存在反向代理的静态目录之外。

启动示例

```sh
node relay/broker.cjs --state /var/lib/YOUR_SERVICE/registry.json --port 18180
```

启用时会初始化 registry 中的 `sponsorship` 字段，并将 registry 的名额上限设为配置值（最高79）；原授权、域名及每日额度保持不变。变更前备份状态，已有授权也计入总名额。不要把线上 registry 或真实审核密钥放进仓库。需要暂停新申请时设 `DSH_RELAY_SPONSOR_ACCEPTING=0` 并重启；已有编号仍可提交，待审核申请仍可处理。关闭整个入口使用 `DSH_RELAY_SPONSOR_ENABLED=0`；已签发的基础档仍执行月额度与文件限制。

手机、桌面的“更多 → 主机与连接 → 云服务器中转”直接显示申请链接，“关于与维护”的赞赏弹窗和管理页支持弹窗复用同一入口组件；不再依赖点击隐藏按钮或一次云端探测决定是否显示。暂停、满额和已有申请查询由申请页明确呈现。客户端不包含审核密钥或个人申请信息。换用其他控制域名时，需同步修改 `public/sponsor-entry.js` 与网关的中转配置。

公开能力查询允许跨域读取；个人申请和审核接口没有跨域许可。审核使用 Authorization Bearer，无 Cookie 登录；审核页面只在内存中持有密钥，退出时清除。Nginx 不得记录 Authorization、查询参数或请求正文，并应保持禁缓存设置。

默认使用 socket 地址限流。若 broker 只接收受信反向代理的连接，且代理覆盖客户端传入的 `X-Forwarded-For`（示例为 `proxy_set_header X-Forwarded-For $remote_addr;`），可设 `DSH_RELAY_TRUST_PROXY=1`。应用读取该头首跳地址，首跳无效或缺失时回退到 socket 地址。草稿和提交继续共用每 IP 每分钟 20 次的额度。发码独立限流，每编号 24 小时 5 次、至少间隔 60 秒，每邮箱 24 小时 10 次，每 IP 每小时 20 次。

## 运营端发码进程

云端只负责排队和验码。运营端本机进程保存现有邮箱的登录信息，并以审核 Bearer 调用以下接口，目标是在排队后 1 分钟内发出验证码。

1. 进程可发送时定期 `POST /sponsor/api/admin/heartbeat`，例如每 30 秒一次。云端超过 90 秒未收到心跳即视为离线，重启后等待下一次心跳。
2. `GET /sponsor/api/admin/verifications` 读取按请求时间排序的待发列表，每项含 `id`、`email`、`code` 和毫秒时间戳 `expiresAt`。用本机邮箱发送该验证码，并丢弃已过期的项目。
3. `POST /sponsor/api/admin/verifications/:id/result` 回报 `delivered` 布尔值，失败时填写 `reason`（简短、可向申请人展示的失败原因）。请回传该项 `expiresAt`，防止迟到的旧回报清除重发后的新码。同一批次可安全重试回报。云端在回报后从待发队列移除该项，保留验码所需的哈希、过期时间和尝试次数。

队列读取不会领取或删除项目。运营端应以单进程处理，并用 `id` 和 `expiresAt` 识别同一批次，发送后优先重试回报。不要将验证码、审核 Bearer 或邮件凭据写入日志。

启用赞助入口时 HTTP/隧道监听器连接上限为1024，原先256不足以容纳79台网关各自的控制与备用连接；实际容量仍需按带宽、内存和并发实测。图片及基础档 API POST 缓冲请求全局同时最多4个，单请求正文最大16MiB；付款截图请求正文同时最多4个、最大3MiB。不要将“低 CPU”视为带宽和维护成本已验证。

## 私有状态、备份与恢复

- `registry.json` 保存授权公钥、有效期、申请邮箱、金额、审核状态、到账交易编号摘要和加密交付密钥。验证码只以哈希及待发期间的加密密文保存，明文由审核鉴权的队列接口返回。发码限流记录只保留所需的时间、编号及邮箱/IP 摘要。申请和授权在同一排他锁、fsync 及原子替换事务内更新。
- `sponsor-proofs/<申请编号>`：私有付款截图（目录0700、文件0600），不属于静态目录，仅审核接口可读。Windows 需额外配置 ACL。
- `monthly-quota.json`：基础档月额度持久账本，沿用预留记账机制；异常退出可能保守多计不足64KiB，重启不能恢复已用额度。错误或损坏时停止传输，不回退无限额。
- 审核密钥同时用于 AES-256-GCM 加密交付密钥。必须私密备份并保持稳定；直接更换该密钥会导致历史待发正文无法解密，不是无损轮换流程。运行中的网关私钥只在用户电脑上，不上传云端。

备份/恢复应暂停所有 registry 写入及中转进程，成组保存 registry、两个额度账本、截图目录和审核密钥，防止只恢复 registry 使流量账本回退。按实际留存政策定期清理不再需要的付款截图与联系方式；首版不自动删除已提交的付款证据或自动释放其名额。清理时先处理争议/退款并备份，不得复用旧交易编号或旧租户域名。旧交付正文在授权过期、撤销或后续续期轮换密钥后不能再读取。

## 验收

```sh
node --test tests/sponsorship.test.js tests/sponsor-portal.test.js tests/relay.test.js tests/relay-settings.test.js
npm run check
```

验收必须使用临时目录和测试密钥，不读取真实 `~/.dsh-remote`。测试覆盖名额预留、付款表单校验、审核鉴权与截图隔离、流水防重复、重复提交/审核幂等、加密交付与重启、月底有效期、续期保留设备绑定、月额度跨天/重启、文件接口拒绝、图片格式校验及原中转回归。`tests/sponsor-portal.test.js` 覆盖查询恢复及退出后的迟到响应；`tests/relay.test.js` 用隔离 TLS broker 完成申请→审核→客户端绑定→月额度→文件拒绝→发送标记→撤销三端闭环。正式启用前还需运营者用真实微信小额到账完成一次人工审核、人工邮件发送及手机连接验收；本地自动化不会访问支付账户或发邮件。
