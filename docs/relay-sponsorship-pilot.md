# 基础中转赞助试运营

本功能为可选的云端设施，默认关闭。本地构建、提交开发代码不会部署、收款或发送邮件。2026-11-01 已按用户指令在现有试运营控制域名部署并启用，详见[上线与入口清理记录](sponsor-live-2026-11-01.md)。

## 已确定的规则

- 单次微信赞助 **1 元及以上**，人工核验到账后开通一个月；更高金额不增加期限、额度或设备数，不开放多月预付。
- 首次开通从审核通过时开始，按北京时间同日同时间至下个月；下个月没有该日期则取当月最后一天。续费从原到期时间加 30 天，不从支付或审核时起算。
- 每个服务月上传与下载合计 **5,000,000,000 字节**；使用独立 `monthly-quota.json`，不在午夜重置。统计包含隧道内 HTTP 头、正文及 WS 帧，不含 TLS/TCP 和控制握手开销，与云厂商账单不完全相同。
- 一个资格绑定一个网关公钥，无法同时或轮流绑定另一网关；续期保留原公钥和公网地址，轮换开通密钥。重装丢失私钥或换设备须联系运营者处理，首版没有自助换绑。
- 开放对话图片预览，计入额度；文件浏览、上传、下载、文件收件箱、会话文件下载及导出接口返回 `403 FILE_TRANSFER_NOT_ALLOWED`。本地 `/fs/file` 只放行 PNG/JPEG/GIF/WebP 图片读取，附件 RPC 只放行经过格式检查的图片结果，单图最大 12MiB，不接受范围读取。图片可被截图或保存，不承诺技术上阻止图片另存。
- 限制的是 Remote 的文件传输接口，不是内容审查或通用数据防泄漏；用户仍可在 DSH 对话中执行任务、查看文本和工具输出。

历史先行测试授权由云端单独标记；App 中转设置显示「特殊先行测试用户」，不把它归为基础档，也不因此改变配额或传输策略。更新后的中转服务会通过已认证的控制连接提供新有效期，在线的新版主机网关自动保存。若主机本地已经按旧有效期停止连接，可用原开通密钥在原主机重新绑定；已单独过期的手机配对不会自动延长。
- 默认 **79** 个占用名额，试运营可配置到 **85**。有效授权、已提交待审核申请、未过期的未付款草稿和到期后的 7 天续费保留期均占用名额；同一授权的续费草稿或待审核申请不重复占位。并发容量由实例实测决定。

基础档直接进入 broker 的 HTTP 按路径和方法放行。聊天、历史分页、操作回执、事件轮询、已支持的扩展和 WebUI 资源继续走原接口。未知路径返回 `403 RELAY_ROUTE_NOT_ALLOWED`；已知文件接口保留原错误码。普通响应按转发字节限制为 24 MiB，客户端安装包路径为 64 MiB，图片仍按原预览规则校验。成功的业务 API 响应须声明 JSON。超过声明的响应大小上限时 broker 返回 502，分块响应超限时中止该响应。

broker 拒绝修改转发路径或方法的覆盖头。`/relay/v1/e2ee` 和 `/relay/v1/plain` 在 broker 内作为字节流转发，应用层接口由主机端处理；云端不能证明改版主机遵守内层路径限制，也不解密会话来检查内容。云端仍执行授权、并发与配额限制，并对两类通道记账及告警。

### 流量告警

- 按授权累计双向记账流量：连续 3 个一分钟窗口每个达到 16 MiB 时告警。每分钟达到 180 次直接请求或通过鉴权的升级通道、12 次策略拒绝或 12 次路由凭证失败也分别告警。隧道计数是外层连接数，不是内层 HTTP 请求数。
- 月配额耗尽或账本不可读会触发告警。每授权、每类信号以 15 分钟去重。告警仅供人工调查；原有拒绝、配额和撤销逻辑独立执行，不因异常信号自动封禁。
- `/sponsor/admin` 经审核密钥鉴权后显示进程内最近 100 条告警，随申请列表刷新；结构化事件也写入中转服务日志，历史留存由服务日志策略决定。事件不含请求路径、正文、付款信息或凭证。
- 分端统计会区分客户端请求拒绝（例如路由鉴权失败、传输协议不符）、主机侧明确返回的 HTTP 错误（包括 403/426/503）和中转自己的缓冲、并发或账本异常。同一原因跨授权累计一分钟内达到 12 次会告警，按原因去重 15 分钟。后台展示次数和最近发生时间，进程重启后累计重新开始。
- 控制连接消失、工作通道等待超时或传输中断只标为「未定位」，可能涉及主机、网络或中转。分类表示观测位置，不等于根因或责任。中转不读取加密通道内部的 HTTP 响应；未到中转进程的客户端或反向代理错误也不在这张统计中。历史状态码不会被补算成分端结论。

### 手机运营看板与提醒

- 在服务的私有环境文件设置 `DSH_RELAY_SPONSOR_OPERATIONS_TOKEN`。可用 `node -p "require('node:crypto').randomBytes(32).toString('base64url')"` 生成独立凭证。手机或电脑打开中转控制域名的 `/sponsor/monitor`，输入只读密钥。页面可加入手机主屏幕，前台每 30 秒更新。数据接口 `GET /sponsor/api/operations` 使用相同的 Bearer 鉴权，只返回汇总数字。
- 看板分别显示待审核订单、已通过订单、有效资格、已绑定和在线主机。配对统计来自在线主机上报的有效端到端加密设备，表示已签发的有效配对。离线主机和未上报的主机显示为未知。近 60 分钟流量按进程内实际记账汇总，服务重启后重新开始。服务期额度以持久化账本为准。
- 成功提交的新订单和上文的流量告警会触发提醒，30 秒内同类事件合并。发送失败会重试，最终失败记录在中转日志中。提醒只包含告警类型、数量和监控入口。进程重启时尚未发出的批次会清空，待审订单仍可在看板上查询。
- 可通过 Hermes 转发，详见 [Hermes 审核与运营提醒指引](hermes-relay-approval.md)。也可复用已配置的 Resend 发信能力，把 `DSH_RELAY_SPONSOR_ALERT_TO` 设为运营者邮箱。两个渠道都配置时使用 Hermes。

## 申请与人工审核

用户访问中转控制域名的 `/sponsor/`：

1. 有剩余名额时可全天获取申请编号。编号预留 90 分钟，先保存完整的私密查询凭证，再按页面提示付款。
2. 填写接收邮箱后可以试发邮件。邮件里的链接会打开确认页，用户点「确认已收到邮件」后记为已确认收信。试发为可选项。
3. 用微信赞赏时备注申请编号，填写金额并上传付款截图。截图支持 PNG/JPEG/WebP，最大 2MiB。提交后保留名额等待人工审核。
4. 在原申请页查询进度、查看运营回复、补充说明和领取开通密钥。换浏览器时粘贴私密查询凭证恢复。查询凭证只经 Authorization 传输。已付款但编号到期时，保留付款记录并在原申请留言。

运营者打开同一控制域名的 /sponsor/admin，输入专用审核密钥：

1. 在微信收款端核实真实到账、金额和付款备注，登记实际交易编号并审核。每个交易编号只能开通一次。
2. 审核通过后，用户在原申请页点击「领取中转密钥」。过期、撤销或续期替换后的旧密钥无法再领取。
3. 在申请列表查看「用户有新留言」，打开对应申请回复。申请人勾选邮件提醒且已确认邮箱时，可以发一封固定文案的回复提醒。
4. 未通过、撤销和退款等处理说明可通过申请状态及留言告知。暂停新申请时，已有申请仍可办理和留言。

客户端先在网关 `/relay` 或管理别名 `/admin/api/relay` 绑定从原申请页领取的密钥。启用加密中转的主机推荐使用支持自动配对的 Android App：先连接主机局域网地址，再到「设置 → 云中转」中的公网配对区，成功后自动添加公网地址并保留局域网连接。尚未更新到统一页面的 App 可在原「主机与连接」页找到此功能；普通浏览器和鸿蒙不支持自动配对入口。未启用加密中转的主机仍可按原来的公网地址和 Remote 访问令牌连接。配对失败时可在同一区域展开「配对日志（可复制反馈）」并发送给运营者，日志不含访问令牌、设备密钥或路由凭据。状态包含 `quotaPeriod`、`monthlyLimitBytes`、`fileTransfer`，在首条流量回报前也能说明月额度、单网关和文件限制；旧每日档保持原有行为。赞助入口会重新读取公开开关，区分暂停/满额与正常申请，暂停或满额时仍可前往查询已有申请。

### 到期后续费

1. 到期后 7 天内，用原申请的私密查询凭证恢复进度，点「获取或恢复续费编号」。从到期时刻到 7 天后的同一时刻（含）可支付不少于 1 元。先获取续费编号、在微信中备注该编号，再提交截图；不要为同一编号重复付款。付款截止为页面上的续费截止和编号预留截止中较早的时间。
2. 运营者核实实际到账时间（北京时间）、金额、备注及交易编号。付款时间符合窗口时，审核可在第 7 天之后进行，但审核不能晚于新服务期；旧服务在审核前保持停用。重复审核不会再次增加期限。
3. 审核通过后，新的到期时间为原到期时间加 **30 天**，独立 5 GB 额度重新开始。原授权编号、公网地址和网关公钥保留，开通密钥轮换。用续费申请领取新密钥，在原网关重新激活；已过期的加密手机配对需重新配对。

超过 7 天不能续原授权；如仍开放，可按新申请处理，不继承原地址。邮箱本身不是原授权的续费凭证。暂停新申请时不能创建新续费编号，但已有编号仍可提交、核验付款和审核。退款或变更邮箱仍需另行核对付款证据。

付款后错过草稿期限、关闭会话丢失查询凭证或无法匹配到账时，保留付款截图与申请编号联系运营者人工处理；不要重复付款。已提交的付款申请不会自动超时释放名额，以免已付款者被静默挤出。运营者应及时审核，并明确约定审核时间与无法开通时的退款安排。

## 部署准备（用于新环境）

沿用 [中转部署文档](../relay/README.md) 中的回环 HTTP 入口、有效 HTTPS、专用控制域名及租户 DNS/证书。需要复制 `relay/*.cjs`、`relay/sponsor/` 及本次使用的赞助码 PNG；不增加依赖，也不改变网关单文件发布形态。随机租户域名必须预先配置通配 DNS 与匹配的证书，或另行安排对应域名；审核通过不会自动签发证书。

通过 systemd 的私有 EnvironmentFile 设置（文件应 0600，仅运行用户及管理员可读）：

```ini
DSH_RELAY_SPONSOR_ENABLED=1
DSH_RELAY_SPONSOR_ADMIN_TOKEN=<独立生成的至少32字符随机密钥>
DSH_RELAY_SPONSOR_MAX_USERS=79
DSH_RELAY_SPONSOR_ACCEPTING=1
DSH_RELAY_SPONSOR_MAIL_KEY=
DSH_RELAY_SPONSOR_MAIL_FROM=
DSH_RELAY_TRUST_PROXY=0
DSH_RELAY_SPONSOR_QR=/opt/YOUR_SERVICE/donate.png
DSH_RELAY_SPONSOR_CONTACT_EMAIL=operator@example.com
```

DSH_RELAY_SPONSOR_MAIL_KEY 为可选的 Resend 仅发信密钥，权限限定在专用发件域。DSH_RELAY_SPONSOR_MAIL_FROM 填该域下已验证的发件地址。邮件通过固定 HTTPS API 发送，应用和站内留言可独立使用。清空任意一项后重启即可停发。DSH_RELAY_SPONSOR_QR 指向微信赞赏码，未设置时默认读取仓库 public/donate.png。申请页使用带 Bearer 的 GET /sponsor/api/applications/:id/qr 读取图片。

启动示例

```sh
node relay/broker.cjs --state /var/lib/YOUR_SERVICE/registry.json --port 18180
```

启用时会初始化 registry 中的 `sponsorship` 字段，并将 registry 的名额上限设为配置值（默认 79，最高 85）；原授权、域名及每日额度保持不变。变更前备份状态，已有授权也计入总名额。不要把线上 registry 或真实审核密钥放进仓库。需要暂停新申请时设 `DSH_RELAY_SPONSOR_ACCEPTING=0` 并重启；已有编号仍可提交，待审核申请仍可处理。关闭整个入口使用 `DSH_RELAY_SPONSOR_ENABLED=0`；已签发的基础档仍执行月额度与文件限制。

Android App 的「设置 → 云中转」集中展示当前主机的套餐、到期时间、用量、公网地址、密钥管理和配对，以及此设备保存的开通登记、审核进度和续费状态。两种状态独立：没有绑定当前主机，不代表没有登记；读不到主机或登记状态时，也不会标记为未开通。既有网页申请可用原查询凭证恢复，不要重复付款。付款、提交材料和找回凭证仍在隔离的服务 WebView 办理，不向服务页注入原生桥接。凭证留在服务源的本地存储中，回到 App 设置只展示登记状态，不返回凭证或邮件地址。领到密钥后仍需绑定主机；云端需同步更新办理页，才能按管理入口隐藏首次开通。换用其他控制域名时，需同步修改 `public/sponsor-entry.js`、`CloudRelayActivity.java` 与网关配置。

公开能力查询允许跨域读取；个人申请和审核接口没有跨域许可。审核使用 Authorization Bearer，无 Cookie 登录；审核页面只在内存中持有密钥，退出时清除。Nginx 不得记录 Authorization、查询参数或请求正文，并应保持禁缓存设置。

默认使用 socket 地址限流。若 broker 只接收受信反向代理的连接，且代理覆盖客户端传入的 `X-Forwarded-For`（示例为 `proxy_set_header X-Forwarded-For $remote_addr;`），可设 `DSH_RELAY_TRUST_PROXY=1`。应用读取该头首跳地址，首跳无效或缺失时回退到 socket 地址。草稿、提交、留言写入和发信入口按来源 IP 限流。邮件共用每 24 小时最多 120 次的全局预算，每申请 5 次、每邮箱 10 次、每 IP 每小时 20 次。试发间隔至少 60 秒。收信链接有效 30 分钟，打开页面后主动确认才会使用链接。回复提醒只向已确认且同意接收提醒的地址发送，使用固定模板并携带服务商幂等键。

启用赞助入口时 HTTP/隧道监听器连接上限为1024，原先256不足以容纳79台网关各自的控制与备用连接；实际容量仍需按带宽、内存和并发实测。图片及基础档 API POST 缓冲请求全局同时最多64个、合计缓冲上限96MiB，单请求正文最大16MiB；付款截图请求正文同时最多4个、最大3MiB。不要将“低 CPU”视为带宽和维护成本已验证。

## 私有状态、备份与恢复

- `registry.json` 保存授权公钥、有效期、申请邮箱、金额、审核状态、到账交易编号摘要和加密交付密钥。收信链接只保存哈希。留言保存在对应申请内，双方的未读状态独立。发码限流记录只保留所需的时间、编号及邮箱/IP 摘要。申请和授权在同一排他锁、fsync 及原子替换事务内更新。
- `sponsor-proofs/<申请编号>`：私有付款截图（目录0700、文件0600），不属于静态目录，仅审核接口可读。Windows 需额外配置 ACL。
- `monthly-quota.json`：基础档月额度持久账本，沿用预留记账机制；异常退出可能保守多计不足64KiB，重启不能恢复已用额度。错误或损坏时停止传输，不回退无限额。
- 审核密钥同时用于 AES-256-GCM 加密交付密钥。必须私密备份并保持稳定；直接更换该密钥会导致历史待发正文无法解密，不是无损轮换流程。运行中的网关私钥只在用户电脑上，不上传云端。

备份/恢复应暂停所有 registry 写入及中转进程，成组保存 registry、两个额度账本、截图目录和审核密钥，防止只恢复 registry 使流量账本回退。按实际留存政策定期清理不再需要的付款截图与联系方式；首版不自动删除已提交的付款证据或自动释放其名额。清理时先处理争议/退款并备份，不得复用旧交易编号或旧租户域名。申请过期或撤销后，留言仍可用于后续处理。

## 验收

```sh
node --test tests/sponsorship.test.js tests/sponsor-portal.test.js tests/relay.test.js tests/relay-settings.test.js
npm run check
```

验收必须使用临时目录和测试密钥，不读取真实 `~/.dsh-remote`。测试覆盖名额预留、付款表单校验、审核鉴权与截图隔离、流水防重复、重复提交/审核幂等、加密交付与重启、月底有效期、续期保留设备绑定、月额度跨天/重启、文件接口拒绝、图片格式校验及原中转回归。`tests/sponsor-portal.test.js` 覆盖查询恢复及退出后的迟到响应；`tests/relay.test.js` 用隔离 TLS broker 完成申请→审核→领取→客户端绑定→月额度→文件拒绝→撤销三端闭环。正式启用前还需运营者用真实微信小额到账完成一次人工审核、云端测试邮件及手机连接验收；本地自动化不会访问支付账户或发邮件。
