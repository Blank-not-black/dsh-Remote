# 独立授权的公网中转试用方案

状态：独立授权中转已实现并部署到隔离试用域名；rc.2 已加入设置页开通和每日 5GB 云端限额，候选包已在本地构建，正在准备公开 RC 发布，未购买新的云产品。实现和操作见 [relay/README.md](../relay/README.md)。拥有者自己的真实 DSH 入口已运行验证；模拟租户授权已撤销，另备五份独立、未绑定的试测邀请，由运营者私下发放。邀请和部署清单不随源码公开。

## 已确认的目标

每位测试者运行自己的 DSH 与 Remote 网关，云服务器只提供公网接入。首批建议 3–5 位开发者；人数是试用范围，不是服务器容量结论。先收集连接成功率、普通 RPC 延迟、实时输出连续性与流量，再决定收费和加速产品。

## 两种凭证，两个权限边界

| 凭证 | 签发方与验证方 | 权限 |
| --- | --- | --- |
| 中转授权码及其绑定的隧道密钥 | 服务运营者签发授权码；云端验证，用户电脑本地产生隧道私钥 | 只允许接入分配给该用户的公网中转入口 |
| Remote 访问令牌／设备密钥 | 用户自己的网关 | 访问用户自己的会话、文件和控制接口 |

中转授权不能替代 Remote 鉴权，不能授予云主机管理权限，也不能访问其他测试者的网关。云端不代填、不保存用户的 Remote 主令牌或模型 API Key。若在云端或边缘节点终止 HTTPS，运营者及受托加速服务在技术上可能接触经过的明文，不能宣称全程端到端加密或服务器无法读取内容。

## 用户操作

1. 运营者创建一份限期授权，例如 7 天、绑定一台电脑；授权码只展示一次，服务端保存摘要。
2. 测试者在 rc.2「更多 → 主机与连接 → 云服务器中转」或插件管理页粘贴个人中转密钥，绑定并开启。旧命令行工具仍可使用；已有本次个人试用可点击接管，沿用原地址和主机密钥。
3. 电脑本地产生独立隧道密钥对，经 HTTPS 注册公钥并绑定授权。私钥留在本机；用户不接收运营者现有的管理员 SSH 私钥。
4. 云端按授权分配独立主机名与隧道身份，返回配对地址；服务端按身份路由，不为每个用户开放公网端口，客户端不能指定其他用户身份。
5. 用户手机添加这个地址，仍使用自己 Remote 网关的访问令牌；可复用现有配对流程，避免要求手机再填写第二份长期密钥。
6. 主机退出或掉线时呈现主机离线；授权到期或被撤销时呈现授权失效。恢复网络后自动重连，不重发尚未确认结果的写操作。

邀请兑换、本地生成密钥、公钥绑定及产品内一键开通已在 rc.2 实现。现有 rc.1 手机仍可访问开通后的 HTTPS 地址，但设置入口及主机内置客户端需要 rc.2。

## 云端隔离

每份授权包含 grantId、状态、过期时间、绑定公钥/指纹、分配域名，以及独立的连接与用量统计。用户可读信息与运营管理信息分别返回，不向其他用户暴露主机路径、凭证或会话内容。日额度按授权持久化；进程内统计快照单独保留，尚非收费计量。

多用户首版采用主机主动建立的 HTTPS Upgrade 隧道，服务端通过 Ed25519 随机挑战签名鉴权，预建备用工作连接以减少每次请求的握手等待。不签发操作系统账户或 SSH 权限，不提供 shell、SFTP 或通用代理。旧单用户 SSH 回连保持原样，未修改 SSH 服务配置或管理身份。

独立主机名保持浏览器存储与同源边界，避免把不同人的 UI 只挂在同一域名的不同路径下，造成根路径请求或存储串用。首批可逐个配置域名/证书；后续再评估泛域名证书与 DNS 自动化。

授权撤销和到期同时阻止新连接、关闭已建立的隧道及其 HTTP/WS 会话，默认每 500ms 检查授权，返回明确失效状态。自动化测试覆盖已建立的连接关闭，云端模拟双租户验证了撤销一方不影响另一方。

## 5 Mbps 下的试用策略

- 优先保证控制请求与实时事件。首版文件接口全局最多 2 路，每路上传和下载分别 100 KiB/s；普通控制请求与实时事件不经过该限速器。根据活跃用户实测调整，不从剩余流量推算并发容量。
- 按授权统计出入站字节、活跃连接、重连次数、普通 RPC 耗时。长期 WS 需要连接期间计数，不能只靠连接结束时才写入的访问日志实时控制配额。
- 授权具有有效期、单主机绑定与撤销状态；每日上传与下载合计 5GB，北京时间零点重置，由服务端持久记账并对 HTTP/WS 执行。超额断开传输，零点恢复，不接支付、不承诺价格。
- 日志只记录匿名授权标识、类别、状态、字节及耗时，不记录正文、令牌、授权码、Cookie 或带凭证的查询串。

## 腾讯云 CDN / EdgeOne

按 2026-10-16 查阅的官方文档：[EdgeOne 支持 WebSocket](https://cloud.tencent.com/document/product/1552/73071)，需显式开启；文档所述 1–300 秒是无数据收发时的连接超时，不应解释为所有连接每 300 秒固定中断。现有网关使用 RFC6455 Ping/Pong，接入后仍须验证边缘节点的实际空闲处理、流式输出与降级行为。

[官方功能对比](https://cloud.tencent.com/document/product/1552/103865)区分普通 CDN 的静态分发与 EdgeOne 的动态内容加速；两者资源包不互通。

拟定路径：手机 → 可选 EdgeOne → 云服务器 → 用户的加密隧道 → 用户 Remote 网关。普通静态 CDN 可以承担前端静态资源；聊天、控制 RPC、文件与鉴权不能被误当作公共静态内容缓存。

接入前需要验证：

- `/api/*`、`/remote/*`、`/fs/*`、`/admin/*`、`/stats*`、`/diagnostics`、凭证和个人状态等动态路径不缓存；其他非静态路径默认也不缓存。仅对明确的公共静态资源制定缓存规则。
- Authorization、Origin、WebSocket Upgrade 和短期票据正确传递；边缘和源站日志同样脱敏。
- 写请求禁止边缘自动重试；流式响应不缓冲，上传续传及长轮询可正常完成。
- 域名区分租户，回源鉴权和可用性探测不会绕过租户授权；同时覆盖源站直连路径，不能只在 CDN 上检查授权。
- CDN/EdgeOne 主要作用于手机到云端这一段；用户电脑到云端的线路、主机是否在线及源站出口带宽仍要实测。额外一跳也可能增加延迟，必须与现有直连入口做 A/B 对比，不能承诺必然更快。

目前不购买或切换 CDN。独立授权与隔离已实现，下一步先收集手机和少数开发者的实际数据。主机隧道使用自定义 HTTPS Upgrade，并非 WebSocket，控制域名应保持直连源站，不能因 EdgeOne 支持 WS 就推定支持本隧道。

## 开放给测试者之前的验收

1. 未授权、伪造、过期、已撤销的凭证全部拒绝；授权码注册重放、并发兑换和换绑有明确规则，不发生一份授权绑定不同主机的竞态。
2. 两个隔离测试主机同时在线；各自只能连接自己的入口，无法抢占域名、端口、身份，不能相互读取会话或文件。
3. 自定义隧道身份不对应操作系统账号，不提供命令、交互 shell、SFTP 或通用端口转发；运营者原有管理身份不受影响。
4. 现有 HTTP、长轮询和 WS 连接在撤销后收口；到期授权不会因为连接持续在线而无限延长。
5. 断网、网络切换、隧道退出、网关退出、DSH 退出分别展示正确状态，自动恢复不会重复提交写操作。
6. 没有新增网关/插件/App 第三方依赖，不改变单文件网关与零构建前端形态；先在临时目录和模拟主机验证，再在独立试用槽位验证，不中断当前用户正在使用的入口。
7. 凭证、过期、串用与撤销属于权限边界，必须有自动化测试和独立的运行验证。源码测试通过不等于可直接向测试者发放授权。
