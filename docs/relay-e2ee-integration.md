# 原生客户端端到端加密中转（试验性，未部署）

2026-11-02。本轮把[隔离原型](relay-e2ee-prototype.md)接入实际 broker、RelayClient、内置单文件网关和 Android 包内 WebUI，并提供用户可选模式。**新开通的主机默认提供加密能力，新配对的手机默认开启端到端加密；关闭必须确认风险。** 线上服务未更新，不能把现有赞助公告改成“已支持端到端加密”。根项目发布元数据仍为 0.8.3。

## 用户开关与默认值

- 开关按 App 内的主机公网 origin 分别保存，影响该手机的 WebUI、WS、后台接收和更新，不会替其他手机或其他主机关闭加密。
- 未配对显示“默认开启，待本地配对”，不能标成已加密。支持加密且开启后，证书错误、连接失败或旧 broker 不兼容均报错，不自动关闭。
- 每次从开启切到关闭都弹出警告：中转方在技术上可读取对话、图片与 Remote 访问令牌，泄露令牌可能导致主机被操作和模型额度被消耗；外层 HTTPS 保留；选择按主机保存且重启后继续有效。取消不调用模式修改 API，不提供免提示选项。
- 关闭后设置页持续显示显著警告。重新开启前检查系统 TLS 1.3 与已保存证书，实际建立连接仍需远端证书校验；失败保留原设置，不替换证书、不自动降级。
- native 层只承认带本轮 `disclosureVersion=1` 的显式关闭记录。旧配对、导入文件中自带的关闭字段、缺失确认版本的记录均按开启处理。重新导入同一主机配对保留其已确认的选择。
- 切换先保存模式并重建本进程代理，断开旧的原生请求和 JS 连接。已经被主机受理的任务不会自动取消；结果不明的写入不自动重发。
- 原有尚未启用加密能力的主机配置不在升级时悄悄更换协议；界面应显示待配对。维护者可从主机本地管理页启用加密入口，也可通过 `DSH_REMOTE_RELAY_E2EE=1` 迁移，或用 `0` 明确保留旧主机模式；新开通无环境覆盖时会持久保存启用能力。

## 链路和凭证

```text
Android 包内 WebUI / 后台接收
  → 本进程随机端口、随机路径的回环适配器
  → 系统 SSLEngine TLS 1.3（核对本地配对证书）
  → 系统校验证书的外层 HTTPS Upgrade
  → broker 仅转发和计量内层 TLS 字节
  → 已认证的主机 work 通道
  → 主机内层 HTTPS 端点（无额外监听端口）
  → 套餐限制 → 回环 Remote 网关 → DSH
```

外层 `GET /relay/v1/e2ee`、`Upgrade: dsh-e2ee-v1` 使用独立的 `Authorization: DSHRelay <路由凭证>`。路由凭证仅允许占用该租户的受限通道，不提供 Remote 访问权限。每个设备使用独立路由凭证。主机控制连接声明其 SHA-256 摘要、设备标识/到期时间、套餐和 `allowPlain` 能力，连同 nonce、主机身份、角色和会话一起签名；broker 检查套餐与当前授权一致。过期、撤销、套餐变化和额度不可读均关闭相关流，不影响其他租户。

明确关闭后使用 `GET /relay/v1/plain`、`Upgrade: dsh-relay-plain-v1`，仍校验外层 HTTPS 证书并携带路由凭证，主机侧执行同一套餐和网关鉴权。该模式不建立内层 TLS，**云端能够读取内容和 Remote 令牌**。不支持明文模式的主机会拒绝这条路由，不能把失败当作改走普通公网 HTTP 的理由。Node 参考客户端也必须显式设置 `mode:'legacy', acknowledgeDisclosure:true`，默认仍为加密。

每个设备另有独立的内层设备秘密，随 `X-DSH-Relay-Device` 在内层发送，主机按摘要鉴权并在转发前移除。知道外层路由凭证或 Remote 令牌都不能替代它；关闭加密后，中转方也能读取该秘密。Remote 令牌、HTTP 路径/正文和 WS 握手均在内层发送。内层使用主机独立的 P-256 自签名 X.509 证书，生命周期一年，完整 TLS 1.3 握手后才发送应用请求。证书与公网域名证书、主机 Ed25519 中转身份及赞助开通密钥分开。配对客户端固定信任证书指纹，禁止自动更新 pin、忽略验证、重放写入或降级旧传输。

证书由 Node 内置 crypto 生成和签名，DER 仅编码固定的 X.509 v3 结构（SAN、用途、有效期、随机序号），不要求主机安装 OpenSSL，也没有引入第三方库。Windows 在新私有目录写入前通过系统 .NET ACL 限定当前用户及 SYSTEM，失败即停止；其他平台使用目录 0700、文件 0600。已存在但损坏、过期或不匹配的身份会拒绝加载，不自动更换密钥。

## 本地验收方式

以下步骤仅供明确控制自己主机和中转服务的维护者使用，不代表已经为生产服务启用。

1. 中转服务使用本轮 `relay/*.cjs`，包含新的 `http-headers.cjs` 和 `file-rate.cjs`。原 HTTPS/租户域名与主机隧道架构继续使用。Node 参考客户端为 `relay/e2ee-connect.cjs`；它先校验配对记录，再发送外层路由凭证。
2. 新开通默认启用主机能力。已有配置从主机本地 `http://127.0.0.1:8787` 的中转设置中启用加密入口，操作前保留本地管理页面；旧公网入口会停止使用。此操作只影响当前主机，不会升级云端服务。
3. 在本地“中转设备与配对”填写设备名和 7/14/30 天有效期，创建设备并保存配对 JSON。最多 32 个有效设备，到期时间同时受中转授权、主机证书约束。配对秘密只在创建时返回，不可从设备列表恢复；结果不明时先刷新列表，撤销旧条目后重新创建。创建/撤销会短暂重建当前主机的中转连接，已受理任务继续运行。
4. 将下载的 **dsh-remote-device-设备标识.json** 通过可信本地方式交给对应手机。不要复制 `identity.json`，不要公开配对文件。主机的 `e2ee/identity.json` 保存证书和私钥，`e2ee/devices.json` 仅保存设备秘密与路由凭据的摘要。旧共享 `e2ee/pairing.json` 不再导出，升级后必须重新创建独立设备配对。默认私有目录为 `~/.dsh-remote/relay-pilot/integrated/e2ee/`。
5. 安装本轮 APK，在“更多 → 主机与连接 → 云服务器中转”的“端到端加密配对（试验）”导入文件，并确认来源、目标公网地址和指纹。需要系统支持 TLS 1.3，不支持时入口明确提示。
6. 如果当前已认证主机的中转状态同时证明该证书指纹和公网地址，App 可以沿用此主机的当前凭证切换连接；否则只保存配对，需手动选择对应公网地址并填写那个主机的访问令牌。不会把 A 主机的凭证自动发送给 B。

App 配对存入私有 SharedPreferences，沿用现有 `allowBackup=false`。配对按公网 origin 隔离；每次进程启动重新生成回环端口和路径，不将这些临时地址写入连接配置或交给系统持久任务。移除最后一个同地址连接会清除其路由秘密并保留“必须重新配对”的标记；全部清理移除持久配对，当前进程保留拒绝旧请求的最小标记，防止尚未退出的后台请求重新走明文。

**提供配对能力的主机拒绝原有 HTTP/WS 中转请求，返回 426。** 用户通过 App 开关选择两条有路由鉴权的通道，不能把用户关闭开关等同于开放无配对入口。旧版 App、普通浏览器和鸿蒙仍不支持这两条配对入口；主机原有局域网入口不受影响。用户选择仅 HTTPS 无需重启主机，也不影响其他手机的加密连接。

本地管理页可撤销单台设备，也可明确确认后更换主机证书并清空全部设备，随后逐台重新配对。主机每次请求校验设备凭据，到期/撤销后的长连接最迟在下一次 1 秒巡检关闭；设备列表不含秘密。本地管理 API `/relay/e2ee`（管理路径 `/admin/api/relay/e2ee`）要求主机管理令牌、真实回环来源、匹配的本地 Host/Origin，并根据实际网关 TCP 连接识别中转来源；从中转到达的请求即使伪造本地 Host 也被拒绝。损坏或过期的证书不会自动替换，显式更换可恢复；轮换中断导致状态不一致时保持拒绝访问。二维码导出、远程自动换证和鸿蒙适配不在本轮范围。

## 传输、计量与套餐

- broker 按租户提供最多 32 条活动通道，等待池有界，转发遵守流背压；外层请求不能指定目标 IP/端口。主机 TLS 端点只转发固定回环网关，最多 16 个活动 HTTP 请求。
- 加密模式上传和下载的内层 TLS 字节都计入额度，包含内层握手、记录头、认证标签和加密开销；关闭后计量内部 HTTP/WS 字节。两种模式仍不计外层 TLS/TCP 及控制通道。这一口径差异需在正式开放前明确告知用户。
- 月额度使用既有持久账本与审核服务月边界；用满、撤销和到期断开已有流。独立身份重建/网关重启不会重置账本。
- 基础档的文件路径拒绝、RPC 包装检查、图片大小/魔数检查及 WS 下行路由白名单在主机解密后执行，套餐来自保存的开通配置，并在 broker 控制认证时交叉核对，不接受浏览器自报套餐。缓冲图片/请求最多 4 份；标准档保留文件传输的两路限制及每路 102400 字节/秒限速。
- Android WebUI 的 fetch（含 Request、取消信号）、XHR 和 WebSocket统一映射到原生通道。配对变化时取消旧请求/连接。后台轮询、峰谷提醒和 APK 更新复用同一私有配对路由；不能在失败时直接请求公网旧接口。
- 配对模式的文件下载使用 App 内两路有界流式下载，经同一原生通道保存到 Android 10+ `MediaStore.Downloads`，完整接收后才发布文件；拒绝重定向，失败/撤销删除未完成文件，进程中断后下次启动清理自己记录的未完成条目。已经发布的文件保留。URL、令牌和临时回环能力不交给系统 DownloadManager、不持久保存、不自动续传。Android 10 以下不支持此保存路径；基础赞助档仍不含文件传输。未配对下载保持原系统路径。参见 [Android Downloads API](https://developer.android.com/reference/android/provider/MediaStore.Downloads)。
- 两种配对模式都拦截外部浏览器导航，需要主机本地打开管理页。不能把网页经过中转重新下载当作可信加密客户端。

TLS 防重放不等于业务幂等。回执丢失时仍沿用 `operations` 查询结果，不自动重发 POST。设备、系统或客户端被控制，以及来自外部网站的内容、赞助表单/付款截图，都不属于本通道的保密承诺。APK 沿用项目既有公开侧载签名，不能将该签名本身作为抵御恶意客户端替换的保证；须从可信来源安装，客户端供应链仍在信任边界内。

## 已验证和待验收

隔离测试使用临时 HOME/USERPROFILE/文件根、清除代理和固定夹具令牌，不读写真实配置，也不请求线上服务。

- 实际 broker + RelayClient + 主机 TLS 端点：双租户 HTTP、图片、WS、原网关鉴权、错误路由凭证、基础档限制、配额和撤销；外层捕获不出现 Remote 令牌、内部路径和正文。
- 实际单文件 gateway 子进程：开通/停用、管理权限、受限身份目录、API 不返回私钥/路由凭证、重启后证书不变、本地接口与加密公网接口同时可用。
- Android 使用的纯系统 Java SSLEngine 与实际 Node 链路互通，回环适配器可用；错误配对 pin 和另一个主机的有效证书都在发送应用凭证之前拒绝；缺少本进程回环路径能力的请求被拒绝。此项是 JDK 互通测试，不能替代 Android 系统供应商实现的真机验证。
- WebUI 覆盖 fetch/Request/XHR/WS、取消、失败不回退、无桥浏览器保持既有方式，以及缺少当前主机身份证明时不自动复用凭证。
