# 会话、历史与发送结果

[首页](README.md) · [日常操作](operations.md)

## KB-SESSION-01：历史一直加载、计数非零却空白

**先看：** 是一个会话还是全部会话；当前服务器/工作区/会话是否正确；显示的是缓存还是主机结果；本地操作日志中的 cache、load、render 阶段，以及 mux/host 错误。

**判断：** 读请求超时、IndexedDB 等待、格式迁移失败与渲染失败需要分开。历史总数不等于当前页有可显示消息；缓存计数也不证明本次主机读取成功。

**下一步：** 先用页面“重试”“加载更早记录”，保留当前失败阶段；迁移错误走 KB-SESSION-02。切换主机后旧响应不应覆盖新会话。不要先清除全部数据，否则会丢失缓存、连接设置和排障线索。

**验收：** 同一会话的主机历史可读取，记录与时间顺序正确，分页/回到最新可用；切网后恢复且没有永久加载。UI 正常不等于原会话所有历史都已核验。

## KB-SESSION-02：migration-required、fallback、instruction-hint

**先看：** `session/migration-required` 或 `cannot safely transform unclassified message source`；是否只有特定旧会话失败。

**判断：** issue #18 的根因涉及 DSH 上游迁移器。Remote 识别并隔离单会话观察错误，显示说明与重试；不修复迁移器，不改原始日志。源码/协议回归不能证明报告者旧数据已恢复。

**下一步：** 在 DSH 中检查原会话，并按上游支持的升级/迁移方案处理。不要把 `fallback` 改为 `user`，不要让只读观察批量激活冷会话，或反复全局重连。

**验收：** 坏会话有明确提示；健康会话仍有历史与实时事件；审批仍可达；原日志不被 Remote 改写。原坏会话的完整恢复另行记录，#18 仍是已知限制。

## KB-SESSION-03：发送超时、回执 pending/unknown

**先看：** 当前会话历史、原发送操作的回执、失败阶段与请求 ID；不复制消息正文到公开诊断。

**判断：** accepted 表示主机已接受，rejected 表示明确拒绝，pending/unknown 表示尚不能确定。5xx、断线或响应丢失可能发生在主机已执行之后。

**下一步：** 从“更多 → 审批与操作回执”及会话历史核对原操作；原意图的再次操作应查询/恢复原回执，不另建一次发送。不要把保留的草稿当成“主机肯定没收到”。

**验收：** 原操作进入明确终态，只有预期的一条主机消息；未知期间不发生重复发送。没有旧版未记录的错误信息时，不能事后补出具体根因。

## KB-SESSION-04：插队、思考、分支或子智能体不符合预期

| 现象 | 核对 | 验收 |
| --- | --- | --- |
| 长按没有插队 | 是否开启长按功能、会话是否繁忙、按钮提示和主机是否支持 steer | 已接受请求与真正生效时机分开；当前工具可能继续执行 |
| 手机没有思考或档位无效 | 主机实际模型 ID、模型目录/路由、弱网设置是否隐藏流式输出 | 实时与已完成历史分别看；能选档位不代表提供方执行 |
| 分支后仍在旧会话 | 创建结果返回的目标会话、当前主机、历史边界 | 跳到新分支且可继续；不自动发送提示词验证 |
| 子智能体不在主列表 | “子代理”入口、父会话、已加载层级和 DSH 能力 | 子记录只读；不能把第三方团队当内置子代理 |
| 新会话突然提示旧错误 | 错误所属 sessionId、当前会话、Auto 集成状态 | 旧会话错误不串入；当前会话真实权限恢复错误仍显示 |

没有 `session.delete` 能力时使用归档流程；不要直接删除持久化文件。权限切换与审批操作见 [日常操作](operations.md)，源码依据见 [来源索引](sources.md)。
