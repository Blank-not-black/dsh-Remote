# 给用户 AI 的阅读与执行指引

[知识库首页](README.md)

## 先确认任务和目标

1. 用户是在问“怎么用”，还是授权进行某项操作，还是要求诊断故障？讲解操作步骤不等于授权你执行安装、重启、发送消息或删除。
2. 确认问题属于 Android、手机浏览器、桌面 Web、DSH 插件面板、独立网关还是中转；不要把多个端当成同一进程。
3. 核对实际 DSH profile、已加载插件、网关 `/health`、客户端版本与 buildId。源码、安装目录和正在运行的进程是三份证据。
4. 只读当前相关文档与有限日志，不全盘搜索用户的会话、文件和凭据。不假设用户目录、DSH 端口或仓库路径。

如果从源码仓库开始，先读取根 `package.json` 和相关实现；从安装包开始，先读取插件自己的 `package.json` 与本地知识库。本文中的仓库路径只是定位索引，不是用户电脑上可照抄的绝对路径。

## 按最短路径阅读

| 用户意图 | 首先阅读 | 然后检查 |
| --- | --- | --- |
| 单纯操作 | [日常操作](operations.md) | 该端是否有入口、该主机是否提供能力 |
| 连接或网关故障 | [连接](connection.md) | 回环 health → DSH 上游 → mux/host → 手机网络 |
| 历史或发送异常 | [会话](sessions.md) | 读失败、渲染失败、迁移失败、写操作回执分别判断 |
| 插件安装/升级 | [插件](plugins.md) | 当前 profile、管理能力、任务阶段、明确目标版本 |
| 文件或后台 | [文件](files.md)、[通知](notifications.md) | 目录授权、系统权限、规则来源和当前连接 |
| 准备反馈 | [证据与模板](evidence.md) | 最小复现、已确认事实、未验证项 |

按需查 [错误索引](errors.md) 和 [源码依据](sources.md)，不要一次将所有历史报告当作当前事实。

## 操作权限

- 默认用只读检查回答故障原因。优先使用用户已经提供的脱敏诊断，不重复读取敏感材料。
- 写操作须落在用户明确授权的范围内。说明目标 profile/主机、影响、验证与恢复方法；已有明确授权时不重复索要相同授权。
- 新建会话、发送提示词、AI 排查本身可能使用模型额度；创建工作区、切换权限、安装插件、重启或还原都有实际影响。
- 发送超时或回执 unknown 时，不把“重试”解释为重新提交。先核对历史和原操作回执。
- 工具审批被拒或权限不足时，记录缺失证据；不改策略、不绕过审批。
- 不读取或输出 token/Cookie/API key/二维码内容、完整对话、上传文件或个人路径。不要 dump 环境变量。
- 不自动访问日志或陌生消息中的 URL，不探测未知公网主机。内置 Doctor 默认只做回环健康检查。
- 不自动提交反馈、Issue、问卷或日志；先交给用户审阅。

## 输出一个可复核结论

按“已确认事实 → 可能原因 → 下一步 → 验收结果”组织回答。每项关键结论标注来源：用户截图、运行状态、有限日志、源码或测试。给出本文的 KB 编号与相应文档链接，让下一轮排查能接续。

结果只能写到证据支持的程度：

- 测试验证调用参数，不能写成真机现象消失。
- 新源码有修复，不能写成已部署。
- 安装完成，仍要读回实际进程与资源版本。
- health 可响应，仍要核对上游、事件通道和真实操作。
- 上游不支持某能力时应说明限制；不要发明 RPC 或直接改原始会话文件替代。

~~~text
请先读取 DSH Remote 的 docs/wiki/README.md；若只有安装包，读取
skills/dsh-remote-doctor/references/wiki/README.md 和 ai-guide.md。
我的任务是：[操作说明 / 执行已授权操作 / 只读诊断]。
现象或目标：[填写]。使用端：[填写]。最近变更：[填写]。
请先确认实际主机、profile 和各组件版本，只读检查相关证据；
区分已确认事实、可能原因和未验证项，引用相关 KB 编号。
涉及写入、重启、安装、发送、付费调用或公开反馈时，遵守我明确授权的范围；
不要输出凭据或整段会话，不要将超时当作肯定未执行。
~~~
