# 客户端日志与反馈附件

客户端和网关支持用户自选的诊断附件；线上收集器已于 2026-10-30 完成配套升级并通过实际 HTTPS 链路验收。旧客户端和旧网关的能力仍以其安装版本为准。

## 记录和保留

`public/diagnostics.js` 统一记录 RPC、会话加载和渲染、实时连接、生命周期、公告拉取／展示／确认／投票，以及存储写入失败。每条操作记录阶段、耗时、可识别的错误类别、源码文件名与行列；报告包含客户端版本和构建指纹，便于定位对应源码。

存储快照只统计键数量、字符串长度、旧格式历史缓存数量及各类缓存占用，不包含缓存正文、原始会话 ID、服务器地址或凭据。`storageChars` 等字段以 JavaScript 字符串长度计数，不应直接当作磁盘字节数或系统剩余容量。无法读取存储时 `storageAvailable=false`，不能将零值理解为空闲空间。

日志保留 24 小时，最多 160 条、约 48 KB；保留最近的关键错误，避免它们被普通 RPC 和轮询记录全部挤掉。`snapshot.droppedEvents` 表明有记录因期限或容量被淘汰。该机制不代替旧会话缓存的迁移及容量管理，后者仍按[下一版本缓存处理计划](next-version-cache-cleanup.md)实施。

localStorage 写入失败会记录具体错误类别，并尝试会话存储和独立的 IndexedDB 日志数据库。IndexedDB 只在事务完成后认定保存成功，打开、读写均有截止时间。报告中的 `persistence` 标明各后端状态；全部不可用时仅保留当前进程内日志。异步备份尚未提交时强制结束进程，仍可能丢失最后几条记录。

## 用户选择与上传

手机和桌面反馈页的「附带客户端与网关诊断」默认不勾选。勾选后，可预览本地脱敏报告及网关诊断；崩溃摘要仍是独立选项。未选择诊断时，不生成或发送客户端附件。复制／导出本地日志仍可离线使用。

网关按共享白名单再次过滤客户端报告，再转发收集器。日志不包含对话正文、表单答案、令牌、Cookie、任意错误字符串或完整文件路径。普通反馈的正文及联系方式仍按用户自行填写的内容提交。

收集器保存客户端和网关的结构化诊断，在 JSONL 写入并同步后返回 `clientDiagnosticsReceived`。网关和客户端按报告编号核对回执。反馈成功但没有完整报告回执时，界面明确提示需要复制或导出补充，不能将其显示成完整诊断保存成功。

旧收集器仍可通过 500 字符以内的 `serverInfo` 收到关键摘要，例如存储占用、旧缓存体积和最近错误。如果完整附件被明确以请求体过大拒绝，网关只携带摘要重试一次；网络结果不确定时不自动重发。这个摘要不能替代完整时间线；没有回执时，完整诊断状态保持未确认。

## 收集器升级边界

源码 `ops/feedback-collector/server.py` 必须与 `diagnostic-schema.json`、`public_polls.py` 一起更新，避免丢失线上已有的公开投票统计。白名单由 `npm run sync-plugin` 调用 `scripts/embed-diagnostics.mjs` 从客户端生成；同一脚本将校验器嵌入单文件网关。`npm run check` 会检查两份生成结果。

旧收集器不保存 `diagnostics` 字段，`serverInfo` 最多保留 500 字符，请求体上限为 16 KB。新版收集器将请求体预算提升为 256 KiB，普通正文支持 20000 个 UTF-16 单元，保留报告编号回执并增加正文摘要核验；投票仍按原 2000 字符契约。App、网关和收集器均更新后才能使用完整链路。实际 HTTPS `/health` 现在返回能力、限制及运行源码/白名单摘要，部署和回滚步骤见[收集器说明](../ops/feedback-collector/README.md)。

网关反馈转发使用 30 秒总预算，包含旧收集器明确拒绝请求体后的摘要回退。网络结果不确定时不重发；客户端保留全文并提示先核对。该调整修复实际 HTTPS 上传较大正文及附件时，旧 8 秒预算可能导致「已落盘但网关未收到回执」的问题。网关与客户端改动随下一版本分发，不会因收集器服务升级而自动替换用户安装的程序。

## 验证

`tests/diagnostic-feedback.test.js` 覆盖关键错误保留、存储满后通过 IndexedDB 跨实例恢复、事务回滚、未授权附件剔除、恶意字段过滤、旧收集器无完整回执的提示，以及真实网关 → Python 标准库收集器 → JSONL 的写入与报告编号回执。所有服务、凭据和数据目录均为隔离测试环境。

2026-10-30 另通过隔离网关 → 实际 HTTPS 收集器 → JSONL 验收：20000 个 UTF-16 单元（含 emoji）的合成正文、160 条客户端诊断和网关诊断均完整保存，正文摘要及完整报告逐项匹配，网关返回 `diagnostics.saved: true`。验收中保留两条明确标注测试、不同编号的记录，各仅保存一次；原反馈数据、中央公告和公开投票结果保持一致。第一次验收暴露了旧超时预算问题，未自动重发该记录；第二次使用修复后的网关完成回执闭环。本次没有发布 App 或版本标签。
