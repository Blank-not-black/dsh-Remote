# DSH 文件投递与设备收件箱（第一版）

DSH 可以通过 Remote 的工具向指定接收设备投递单个文件。文件先进入待确认队列；用户在设备前台选择接收后才开始下载。无需邮箱账号或额外云端存储。

## 使用

1. 设备安装含本功能的 App，或打开新版 Remote 网页并连接主机。手机端和桌面端都在“文件”页面显示收件箱。打开 Remote 且保持前台时会登记接收设备；可展开“接收设备”修改设备名称，便于 DSH 区分手机和浏览器。
2. 在 DSH 中提出请求，例如：“把当前工作目录里的报告.pdf 发到我的手机。”DSH 先调用 `remote_devices` 查询设备，名称不明确时应让用户选择，再调用 `remote_send_file`。
3. 当前对话发来的文件会像审批一样显示在对话上方，与目标、任务、提问等组成叠放卡片；每次显示一张，可左右滑动、点分类或箭头切换，也可收起整组。文件卡片可直接选择“接收文件”或“拒绝”；其他会话的文件在“文件”页面处理。卡片显示文件名、大小和说明，展开详情可查看来源会话和有效期；不会自动接收、自动打开文件。新请求会更新分类数量，保持你当前操作的卡片。已处理记录收进文件页的“已处理”分组。
4. Android 使用系统下载服务，保存到 `Downloads/dsh-remote/`，同名文件沿用已有的防覆盖命名。浏览器下载并校验后显示“保存文件”，点击后交给浏览器的下载/保存流程。
5. DSH 可以用 `remote_file_status` 查询本会话的投递结果。设备离线时队列仍保留；24 小时内重新打开 Remote 后可处理。

对话里的文件摘要按“文件名 → 扩展名与大小 → 用途说明 → 接收或拒绝”排列，去掉重复的“等待接收”提示。长文件名和说明最多预览两行，详情保留全文、来源会话和到期时间。浏览器接收后显示“传输校验通过”，仍需点击“保存文件”；校验提示表示传输摘要一致。

本功能不是给已经退出的 DSH 自动发起一次模型调用。工具由当前运行中的 DSH Agent 调用；投递后接收不要求发送工具保持运行，网关需要继续可达。

## 工具

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `remote_devices` | 无 | 列出已登记接收设备的 id、名称、最近前台时间和是否在线；离线设备也可投递。 |
| `remote_send_file` | `path`、`device_id`，可选 `title`、`message` | 投递当前会话工作目录内的一个本地普通文件，返回任务编号、文件摘要、状态及到期时间。 |
| `remote_file_status` | `transfer_id` | 读取本会话发送任务的状态；其他会话的任务不返回。 |

工具需要 DSH 提供 `tools`、`fs`、`workingDirectory` 服务，已在真实 DSH 0.2.1-rc.2 验证注册与执行。服务缺失的旧宿主不注册这三个工具，不阻止 Remote 其他功能加载。实现使用原始 JSON Schema 注册，不新增 SDK 或其他运行依赖。DSH 原有工具权限规则继续适用，设备端接收确认是独立步骤。

第一版仅支持主机本地执行世界、当前会话工作目录内的文件，不支持目录、多文件、外部 URL 或容器路径的自动映射；符号链接不能绕出当前工作目录，网关的文件根与受保护路径检查继续生效。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| `pending` | 已排队，等待用户确认；不能报告接收成功。 |
| `accepted` | 用户已同意，等待开始下载。 |
| `downloading` | 正在下载或等待设备回执，不能报告已保存。 |
| `downloaded` | 浏览器已校验文件并触发保存交接；浏览器不能可靠确认用户最终是否落盘。 |
| `complete` | Android 系统下载服务报告成功，由设备回传；不是网关仅凭 HTTP 发送完毕得出的结论。 |
| `failed` | 文件校验或接收失败，可在设备明确选择重新接收。 |
| `rejected` | 用户拒绝；任务不会再提供下载。 |
| `expired` | 超过有效期，或对应访问凭证已撤销。 |

如果发送工具报告“投递结果未确认”，它会给出确定的任务编号。先查询该编号，不要重复发送。相同会话/工具调用编号对应同一个请求；刷新与收据恢复不会再次创建投递任务。

## 存储、授权与限制

- 单文件上限 50 MiB，有效期 24 小时；每个网关最多 20 个未完成任务、200 MiB 有效文件副本、200 条近期记录。
- 文件发送时复制到主机的 `~/.dsh-remote/file-inbox/`，计算 SHA-256。后续修改原文件不会改变已投递内容；发送期间文件发生变化则拒绝创建任务。下载前复核副本摘要，浏览器也复核收到的内容。
- 接收设备使用独立的随机接收密钥，并与当前访问凭证绑定；只保存密钥摘要到主机。共享访问令牌模式同样需要设备的接收密钥才能读取队列或确认。下载还需要用户确认后签发的短时文件凭证，不能凭任务编号直接下载。
- DSH 工具使用主机现有管理通道创建任务。设备 API 不允许反向创建任务或读取其他设备的队列，撤销访问凭证后既有下载授权也失效。
- 原始路径、管理令牌、接收密钥不会进入发送状态回执；设备侧本地持久化只保存接收身份和系统下载编号，不复制主机管理令牌。清除站点/App 数据会生成新接收设备，旧任务不会自动转交。
- 到期、拒绝或撤销后的文件副本按队列清理流程删除；过期清理在访问收件箱时执行。第一版不提供后台唤醒、推送通知或多设备群发。Android 下载服务可以在离开页面后继续执行，完成回执在重新进入前台后补回。
- 实际下载走 `/fs/inbox-file`，沿用已部署中转对 `/fs/*` 的文件传输并发和限速规则。浏览器下载允许最长 20 分钟，切换主机或凭证时会取消旧请求；首版不提供分块续传。

## 验证范围

自动化覆盖真实 HTTP 网关、两个设备、凭证撤销、确认前阻止下载、固定副本、过期、拒绝、摘要损坏、大小限制、重启持久化、幂等、跨会话查询，以及切换主机后的迟到响应。真实 DSH 注册/调用不消耗模型额度；浏览器用隔离主机验证 320px 手机布局和桌面布局、确认/拒绝、实际文件保存与字节内容。Android 系统下载回执使用已有桥接口并进行模拟测试；手机实体设备尚未验收。HarmonyOS 原生客户端尚未接入本收件箱。
