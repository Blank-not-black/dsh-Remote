# 大小限制审计与对话复制

2026-10-30，独立开发工作树；没有部署收集器或发布版本。

## 限制核对

| 范围 | 当前限制与处理 | 本轮结论 |
| --- | --- | --- |
| 普通反馈正文 | Web/Android 页面、网关和新版收集器统一 20000 个 UTF-16 单元；emoji 通常占 2 个 | 原 2000 限制偏小；输入框删除 `maxlength`，以计数和提交校验代替粘贴截断。超限或失败仍保留全文，可主动复制备份。 |
| 反馈 JSON 请求体 | 网关和新版收集器统一 256 KiB | 原 96 KiB 不足以覆盖长正文、JSON 转义和诊断组合；实测最坏转义的 20000 字符正文携带诊断可完整落盘。 |
| 投票/表单 | 编码后 2000 字符；填空题按题目规则，最多 1200 字符 | 独立的表单契约，不随普通反馈扩容。 |
| 老部署兼容 | 老网关的正文限制、老收集器的正文/请求体拒绝分别显示原因 | 不裁剪正文、不拆成多条、不在不确定结果下自动重发；新收集器返回正文 SHA-256，网关检查不匹配时报告未确认。 |
| 轮询事件 | 每通道最多 1000 条，新增默认 8 MiB 总量目标；环境变量 `GATEWAY_EVENT_BUFFER_MAX_BYTES`，范围 64 KiB–64 MiB | 原先对部分长字符串截为 16 KiB、数组截为 200 项，可能与 WS 内容不同。现在按整个事件回收，不修改正文；至少保留最近一条完整事件，所以单条大事件可超过总量目标。游标落后触发既有 reset/历史重同步。重放基线仍受其原有独立条数限制。 |
| 普通 RPC/写收据请求体 | 4 MiB | 保留上限；修复拒绝后继续累积字符串的问题，统一按 UTF-8 字节读取，超限明确返回 413，不向上游执行该请求。 |
| 公告响应 | 512 KiB | 保留上限；补上 chunked/解压后响应的流式检查，超过限制立即取消读取，不能只看 Content-Length 或读完后再检查。 |
| npm 包级元数据 | 响应 64 MiB、保留字段 1 MiB 字符、20 秒 | 前轮已修复；发布时间和 README 按需流式保留，README 显示前 100000 字符并标明截断。单版本详情仍有独立 8 MiB 上限。 |
| 文件预览/上传/收件箱 | 预览 1 MiB；普通上传默认 2 GiB（可配置）；收件箱单文件 50 MiB | 有明确错误或用户确认边界，本轮保留。 |
| 技能、团队、上下文读取 | 原生响应 2 MiB；技能正文显示 100000 字符并带 truncated 状态 | 属于界面预览预算，本轮保留。 |
| 本地诊断和过程预览 | 日志 160 条、约 48 KB、24 小时；思考/工具预览约 12000 字符；旧收集器 serverInfo 摘要 500 字符 | 属于有界保留或明确预览，500 字符不是反馈正文限制；未将诊断容量扩大为完整会话上传。 |
| Markdown 富内容 | 富内容解析 200000 字符预算，超出仍显示转义源码 | 保留渲染预算；复制原始 Markdown 不经过截断后的 HTML/预览。 |

本轮最初只读核对时，线上收集器仍为 `MAX_MSG = 2000` 的旧版部署。后续已于 2026-10-30 按授权备份并更新收集器、诊断白名单及公开投票模块，通过实际 HTTPS 的长正文和诊断回执验收。20K 完整链路仍要求主机网关、客户端和收集器均支持；部署详情及超时修复见[客户端日志与反馈附件](diagnostic-feedback.md)。

## 对话复制

手机 Web/Android 和桌面对话仅在围栏内容块提供复制入口，不在整条用户/助手回复头部放置「复制 Markdown」。`md` / `markdown` 块只复制该块内部的 Markdown 原文，不带前后解释、围栏或语言标签；多个块各自独立。较长外层围栏中的嵌套代码围栏保留，不会提前截断。

内容块采用一体式窄标题栏，左侧标明 Markdown / 代码语言，右侧为低强调复制图标；图标为 18px，点击区域保持 44px。成功时原位显示勾选与「已复制」，失败才显示错误提示。代码与 Markdown 标记从该块的解码文本复制，不保存第二份全文到 HTML 属性。按钮绑定当前连接、会话及历史作用域，拒绝旧界面残留操作，防止重复点击；README 等非对话 Markdown 默认不新增按钮。
