# 插件面板与管理控制台 UI 全面重构方案

方案日期：2026-10-20。下文保留原始设计，交互演示使用模拟状态。用户选择顶部导航后，已在 RC.7 实施并本地安装；RC.8 根据实用反馈将额度移回插件面板、移除管理页用量分区，并补齐反馈浮层和对话类型选择。当前实现与真实实装证据以 [RC.8 验收报告](rc-0.8.0-rc.8-local-ui.md) 为准。

## 目标和范围

覆盖 DSH 侧栏打开的插件抽屉、插件内管理页 `/remote/admin/` 和独立网关管理页 `/admin/`。在 Desktop 的现有 iframe 内完成导航并提供返回；HTTP/HTTPS 继续适配浏览器打开方式。

重构顺序是：页面职责 → 信息架构 → 状态与任务流程 → 组件与视觉 → 验证。功能保留并重新归位；保持零新增依赖、纯 JS、单文件网关发布形态与六套主题。

设计目标：

1. 打开面板后 5 秒内能判断“能否连接、是否需要我处理”，这是待验证目标。
2. 没装 App 的用户能找到手机扫码下载；装好 App 的用户能直接配对。
3. 日常用户无需穿过首次引导或统计区才能管理设备。
4. 故障时说明已知事实、当前影响和下一步；未知状态不显示为正常。
5. 小抽屉与完整控制台共享状态及组件，布局和内容密度适配各自空间。

## 技能如何影响设计

| 技能 | 采用的方法 | 本项目落点 |
| --- | --- | --- |
| design-everyday-things | 可发现性、操作与结果映射、反馈、约束 | 每个任务区有明确主操作；风险操作与连接操作分离；状态和后续动作就近展示 |
| cognitive-psychology-ux | 渐进披露、识别优先、减少并列选择、相近内容分组 | 按任务分区；初次引导只展开当前步骤；高级设置按需展开；减少重复状态卡和卡片嵌套 |
| ux-researcher-designer | 任务旅程、证据与假设分开、可用性任务和成功指标 | 以首次安装、日常连接、故障恢复三个场景验证；不编造访谈、频率或用户画像统计 |
| visualize | 可交互方案推演 | 对比侧栏与顶部导航，切换首次使用、日常使用、连接异常；只改变演示状态 |

这些是设计依据，不是已经完成的用户研究。尚未测量实际完成率、任务耗时和误点率。

## 当前问题与证据

| 当前结构或逻辑 | 可能造成的体验问题 | 改造方向 |
| --- | --- | --- |
| 插件抽屉依次显示状态、完整三步引导、快捷操作、用量、运行详情 | 小空间承载多个层级；核心操作容易落到首屏之后 | 插件面板只保留状态摘要、当前任务及常用入口 |
| 插件和管理页同时存在运行状态、引导、配对、用量入口 | 用户不易理解两页的分工 | 共享任务组件；面板做摘要，控制台管理完整配置 |
| 管理页从引导一直纵向排列到设备表，包含令牌、自启、网络和统计 | 用户需要记住各项所在的滚动位置 | 稳定的任务导航和可恢复的页面位置 |
| 插件快捷区把停止网关与复制令牌并列 | 高频访问与会中断连接的操作视觉权重接近 | 停止网关归入运行设置，并明确影响 |
| 管理页直接显示共享令牌全文 | 日常查看状态时暴露了不需要的信息 | 默认掩码；显示、复制、轮换分开；配对码在主动操作后显示 |
| `public/plugin.js` 用 `upstream?.reachable !== false` 判定健康 | 上游未知可能被解释为正常 | 明确已确认、异常、未知、处理中和数据过期 |
| 设备表、在线数、设备密钥分别表达连接、IP 与授权身份 | 名称相近而统计对象不同 | 分别命名“在线连接”“授权设备”“访问记录”；无法确定实体设备时不声称设备数量 |
| 页面已有六主题；插件 client 的主题枚举仍只有四个 | 抽屉外壳和页面主题可能不一致 | 全入口使用同一主题清单与语义变量 |

主要源码落点：`public/plugin.html/js`、`public/admin.html/js`、`public/setup.js/css`、`public/relay-settings.js`、`public/insights.js`、`packages/plugin/client.js`。

按 design-everyday-things 的五项二分制做保守源码初评：4/10。错误恢复、能力约束已有基础；可发现性、结果理解、布局映射未整体通过。该分数是启发式判断，不是实测可用性或用户满意度。

## 页面职责与信息架构

### 插件抽屉：快速访问

推荐默认宽度约 440–480px，保留用户所在的 DSH 上下文。小窗口可占满可用宽度，尊重 Desktop 标题栏与安全区。

从上到下：

1. 标题、主机身份、关闭。
2. 一行总状态，下方用三个明确状态描述 DSH、网关、实时通道；异常只突出受影响项。
3. 一个随场景变化的任务区：首次连接 / 添加设备 / 恢复连接。正常情况下只有一个高强调主按钮。
4. 在线连接的简短列表，或“当前没有手机在线”的中性空态。
5. 完整控制台入口；可选的一行今日用量摘要，数据缺失时不占据大卡片。

完整设置、明文令牌、全量统计和停止网关归位到控制台。支持从“显示二维码”或“排查连接”直接进入对应任务，不强迫用户先浏览概览。

### 管理控制台：任务分区

推荐宽屏左侧导航，窄抽屉/手机改成带当前分区名称的导航菜单。次选为顶部导航；信息归属保持一致。

| 分区 | 内容 | 核心操作 |
| --- | --- | --- |
| 概览 | 当前主机、连接健康摘要、在线连接、需要处理的事项 | 添加设备；有故障时进入相关诊断 |
| 设备与访问 | 在线连接、授权设备、访问记录；共享令牌或独立密钥模式 | 添加/备注/移除授权；显示、复制、轮换凭据 |
| 连接网络 | 局域网和 Tailscale 地址、候选地址、云中转状态与配置 | 选择连接地址；按现有能力管理中转 |
| 用量 | Token、API 费用、Plan 等值、套餐额度、数据来源和时间 | 查看现有明细、刷新 |
| 诊断 | DSH → 网关 → 地址 → 设备 → 实时链路的检查及具体失败项 | 重新检测、复制脱敏报告、查看现有修复指引 |
| 设置 | 网关端口、登录自启、运行控制、版本、外观、语言 | 保存配置；按能力启停网关 |

“帮助与支持”放在全局次级入口。版本不在多个概览卡片重复展示。主机 IP 和云中转只在网络区维护；其他页面使用其摘要和深链接。

设备表原有字段全部保留：概览只显示名称/类型、状态、连接地址；请求数、最近活跃、UA 和具体通道放在详情。IP 记录不能自动等同于一台实体设备。

## 三条主要流程

### 首次使用

`确认电脑端可用 → 在手机安装或打开客户端 → 配对 → 核对连接结果`

- 以三步组件呈现，当前步骤展开，其他步骤保留标题和状态；可直接跳到“已有 App，去配对”。
- 第一步以真实服务状态自动核验；进程存在不等于管理接口、上游和通道全部可用。
- 下载优先手机相机扫码，桌面下载和备用发行页作为次级路径。显示当前主机包的版本、体积和可用性。
- 浏览器或系统下载器负责实际下载进度；界面只报告能确认的状态。不把下载点击、手动“已安装”或系统安装页面打开当成成功。
- “我已安装”只负责进入下一步，不改变后端连接状态。
- 配对区集中选择地址并显示连接码；下载码、连接码明确命名，逐步出现。
- 使用现有共享令牌或设备密钥策略，不在 UI 重构中偷偷切换认证模式。独立密钥开启时，走已有创建设备流程。
- 浏览器客户端作为明确替代路径；HarmonyOS 链接到实际自构建说明，不能展示不存在的可安装包。
- 没有在线连接时不凭此认定是全新用户；首次引导进度按主机标识保存，允许主动重看。历史授权/连接信息仅在后端实际提供时用于辅助判断。

### 日常使用

`打开插件 → 判断状态 → 查看在线连接 / 添加手机 → 需要时进入完整控制台`

默认回到上次访问的控制台分区；从插件带任务进入时优先显示对应任务。常规内容不因为轮询重新出现首次教程。

状态正常时不显示修复按钮。当前没有手机在线只显示空态，不渲染为红色故障。添加设备入口稳定，避免在每种状态下改变位置。

### 连接异常

`看到影响 → 查看失败环节 → 执行已有修复动作 → 重新验证`

先说明“网关在线，但暂时无法连接 DSH”等事实，再给下一步。只展示与异常相关的操作；完整检查放在诊断区。

防火墙规则无法自动核验时显示“尚未确认”，不伪造已通过或已阻断。局域网正常而手机打不开时，提示检查同一手机的 VPN / Wi-Fi / 蜂窝网络，不直接要求修改云配置。

## 统一状态与交互规则

| 状态 | 显示方式 | 操作原则 |
| --- | --- | --- |
| 检查中 | 正在读取某个环节，保留布局 | 合并重复读取，不反复闪烁 |
| 已确认可用 | 文本加状态标识 | 满足具体证据再显示，不由缺失字段推断 |
| 部分可用 | 说明受影响能力及仍可用的操作 | 安装包下载不必因 DSH 上游失败一起禁用 |
| 失败 | 问题、影响、下一步 | 就地重试；保留输入 |
| 未知/不支持 | “暂未确认”或明确不支持原因 | 不显示假零或假健康；区分缺数据与平台能力缺失 |
| 数据过期 | 保留上次摘要并标明更新时间 | 配对等凭据操作在身份失效时清理旧内容 |
| 操作进行中 | 显示具体对象与阶段 | 禁止同一写操作重复提交；成功以回读为准 |

统一命名和动作：新手看到“添加手机/设备”“下载 App”“检查连接”，具体网关术语放在对应设置与诊断中。二维码不默认展开，关闭任务即收起凭据。

停止网关、撤销设备密钥、轮换共享令牌都在动作位置说明影响。只对确实会中断当前访问或改变授权的动作提供必要确认；复制地址、刷新、显示引导不增加确认。

## 视觉系统

- 默认延续深空石墨与蓝色强调色；浅色、中性、黑白、大肥鱼等六主题保留。各主题使用相同布局、密度和交互，角色装饰不覆盖文字、焦点或状态。
- 去掉大面积放射渐变、重复状态徽章、无信息价值的装饰和多层卡片嵌套。优先用标题、间距和轻分隔组织内容。
- 正文建议 14px，说明 12–13px，主要标题 20–24px；重要操作和状态不再使用 9–10px 字号。
- 间距统一到 4/8/12/16/24/32px；控件与面板使用少量固定圆角，避免同屏多套样式。
- 状态使用文字与图标共同表达，颜色只作辅助。中断、过期、未知各有明确文字。
- 点击区域以约 44px 为触摸目标；桌面可降低视觉密度，但保留可点击范围。键盘焦点、Esc 关闭与焦点返回完整实现。
- 动效限定在短暂的页面、展开和状态变化，尊重 reduced-motion；轮询不触发入场动画。

## 技术落地

在现有纯 JS 中拆分共享职责，不引入框架、运行时依赖或新的 CDN 资源。

- `public/remote-state.js`（拟新增）：从现有 API 映射出服务健康、客户端计数、能力、数据时间和操作状态；不重定义鉴权。
- `public/remote-ui.js/css`（拟新增）：按钮、状态条、表单行、空态、详情与任务容器；CSS 严格限定在 Remote 管理界面，避免影响手机会话页。
- `public/plugin.html/js`：小面板外壳、摘要和任务入口。
- `public/admin.html/js`：导航、分区路由、页面级生命周期；用单页分区和 hash 路由兼容零构建部署。
- `public/setup.js/css`：把上一轮完整纵向引导改为可嵌入的当前步骤组件，保留现有下载和配对能力。
- `public/relay-settings.js`、`public/insights.js`：沿用现有业务适配；增加挂载、暂停和销毁边界，按分区实际可见性读取。
- `packages/plugin/client.js`：抽屉尺寸、安全区、全主题一致性、导航与关闭行为。
- `scripts/sync-plugin.mjs`、相关测试与文档：同步新增源文件并覆盖运行时路径。

状态数据共享一次读取，页面局部更新。保留可见页面现有及时性，隐藏分区暂停非必要请求；切换主机或身份后通过 generation/AbortController 丢弃旧响应，清除敏感草稿。轮询不能重建输入框、移动焦点、丢失文本选择或回到顶部。

现有 API 能覆盖的信息架构先落地。任何新增健康指标、日志历史、下载遥测或能力写接口都要另行列明契约，不能在原型中假定后端已经提供。Desktop 的同框导航、反向代理 Basic Auth 与独立网关 Bearer 鉴权都需要继续覆盖测试。

## 分阶段实施与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| 基础 | 功能清单、统一状态模型、公共组件、导航和主题规范 | 原有功能有明确归属；未知状态不会变绿；身份与主机切换正确 |
| 主要流程 | 插件摘要、控制台概览、分步安装/配对、设备与访问 | 已装 App 可跳过下载；日常无教程干扰；密钥模式正确；二维码职责清晰 |

## 可用性验证

找至少 5 位未看过新界面的参与者，使用任务描述而非逐步提示。以下是目标，不是已经取得的成绩：

- 首次使用：在 10 秒内找到手机下载入口，完成安装后找到配对入口；记录中断位置与原因。
- 已有 App：两次页面操作以内进入连接二维码任务；不能把打开教程算作完成配对。
- 日常查看：5 秒内正确描述 DSH、网关和手机当前状态；区分“没有手机在线”和“服务异常”。
- 故障恢复：无需指导找到失败环节与下一步；遇到未知防火墙状态不能误认为防火墙已确认故障。
- 设备访问：找到并备注一个连接；理解撤销设备与停止网关影响不同。
- 无数据：能分辨费用未启用、读取失败、缓存过期与真实零消耗。

验证宽度至少包括 360px、520px 抽屉、768px 与 1440px；覆盖六主题、200% 缩放、键盘、触摸、长英文、空列表与多记录。凭据或原始路径较长时允许局部换行/横向滚动，页面不出现整体横向溢出。

核心任务目标完成率 ≥80%，后续根据试用结果再调整阈值。手机系统相机、下载管理器、安装提示、App 配对与弱网恢复必须真机验证；模拟原型和单元测试不替代这些证据。

## 本轮方案交付核对

交互演示包含侧栏分区、顶部导航两个布局，以及插件面板/管理控制台两种视图。已核对脚本语法与本地交互：三个模拟场景、六个分区、跳过安装进入配对、风险动作说明和视图切换。浏览器检查了两个导航布局、配对入口与插件面板呈现。

原型没有后端网络请求，不执行下载、配置保存、剪贴板写入、令牌轮换或网关启停。本轮没有修改产品代码、运行产品全量门禁或构建新的 RC；实施阶段按上文验收。
