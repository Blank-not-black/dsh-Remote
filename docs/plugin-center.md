# 插件中心

> 源码核对：2026-10-15，0.8 开发者预览。[文档首页](README.md)。


当前手机与桌面独立插件页面共用主题卡片，分类和筛选集中到工具栏；启停开关位于卡片右上角，详情、更新、卸载位于底部操作区。待重启提示集中显示在页面，不对所有插件重复标记。手机单列、桌面自适应双列；键盘焦点和减少动态效果偏好继续保留。

0.8 手机端和桌面端从“更多 → 主机插件”进入独立插件页。详情原地展开，并在刷新后保留展开状态与阅读位置。已安装、添加插件和内置插件共用当前服务器的认证连接。

## 功能与生效方式

- 已安装：提供名称/描述和配置状态筛选、版本、详情和组件运行状态；当前 profile 中的官方实验性插件放在默认收起的“实验性插件”折叠区，展开后展示，刷新和筛选时保留展开状态，重新进入插件页时恢复收起。由主机维护的条目保持只读。其余内置插件单独查看，区分配置启用与实际运行，并提示待重启。
- 发现插件：通过当前主机的官方 `pluginMarket` 服务读取已配置索引，支持中文相关性、索引顺序、最新发布、分类与稳定分页，显示主机判定的安装状态及版本兼容性。没有配置索引或服务未启用时显示明确引导；不会回落到 npm 关键词目录，也不会替用户设置索引源。
- “添加插件”页展示 Remote 已适配能力及已核验的精确版本；安装仍先预检、确认，再执行。默认已安装页没有额外的可选功能卡片。完整包名查看详情始终保留。
- 已安装及发现条目的详情可按需阅读 npm 包级 README，正文限 100,000 字符、缓存限 30 个包/10 分钟。README 不按指定版本归档；latest 标签仅供参考。图片仅允许固定白名单 HTTPS 图床，禁止同源 API、data、本地文件及富内容执行；缺少 README 是正常状态。
- 安装、更新：校验目标版本声明 `dsh.bundle.patch`，执行 DSH 自带 `plugin --profile` 命令，固定版本并禁用安装脚本。
- 启用、停用：修改当前 profile 的 bundle 配置，在后续安装或更新时保留停用名单。需要重启 DSH 后生效，不是热启停。
- 卸载：通过 DSH CLI 移除依赖并同步 bundle 列表。不会删除用户的插件数据目录。
- 核心 `@deepseek-ai/*`、非 profile 依赖及 Remote 自身的卸载、启停不允许通过此入口修改。Remote 仅允许经过明确确认的精确版本更新。
- 需要安装脚本、额外凭据或特殊配置的插件，应在主机上完成这些步骤。市场展示不等于兼容性或安全背书。

## 主机与任务边界

### 大型 registry 元数据预检

发布时间核验使用 npm 完整元数据中的 `time`；精简安装元数据不包含逐版本发布时间，不能用它代替。读取器流式校验 JSON，只保留包名和发布时间，跳过 README 和全部版本的安装清单。单包最多读取 64 MiB，保留字段最多 1 MiB 字符，单次请求最多 20 秒；出错时返回包名和已接收字节数。

README 读取使用同一流式读取器，只保留包名、包级 README 和版本标签，避免版本历史过大导致说明页不可读；超长 README 按原有 100000 字符限制截断，继续校验未显示的 JSON。发布时间缓存若缺少本次预检需要的版本，会重新读取一次当前元数据，不能据此跳过年龄核验。官方市场的索引检查和搜索共用 20 秒总预算，避免两段等待累加超过客户端超时。

预检仍检查整个锁文件，保留发布年龄、精确版本豁免及显式确认规则。总预算按每批 6 个包、20 秒计算，最多 120 秒；手机/桌面和网关为预检预留 130 秒。缺少发布时间、损坏或超限的响应均阻止安装，不会自动豁免或跳过相关包。验证和反馈复核见 [issue #28 修复记录](issue-28-preflight-and-feedback.md)。

只从运行中的 DSH 根 `baseUrl` 识别 profile，校验 `profiles/<name>/package.json`；只从当前启动路径识别 DSH CLI。桌面端验证当前 Electron host、安装中的 `@deepseek-ai/dsh-desktop-host` 与 desktop runtime 版本、启动参数中的运行时目录和 profile 根目录，再使用该安装自带的 `lib/cli.js`。无法确认时只读，不搜索全局 CLI 或 PATH，不猜测 `web`，不允许客户端指定主机路径。

API 位于 `/remote/api/plugins/{state,market,details,operations,recover}`。沿用网关 → DSH 插件鉴权链路；插件端仍校验 Remote token。操作参数只接受包名、精确版本、固定操作类型和请求 ID，不接收命令行片段、URL、Git 地址或本地路径。

任务在独立 Node 子进程执行；桌面端显式使用 Electron Node 模式和桌面版自带 CLI/包管理器，支持 ASAR 中的官方入口。窗口关闭或 HTTP 断开不取消任务。每个 profile 同时只允许一个任务；同一请求 ID 可安全重试。客户端连接切换后拒绝继续向原确认页面提交。

记录保存在当前 profile 的 `.remote-plugin-center/`：

- `job-<id>.json`：任务状态与截断后的日志。
- `backup-<id>/`：修改前的 manifest、锁文件、工作区和 patch 文件（存在时）。
- `disabled.json`：通过此入口停用的 bundle。
- `lock.json`：互斥锁，记录启动者、工作进程与 CLI 子进程 PID。
- `launch-<id>.json`：启动 PID 的独立记录，避免启动者覆盖工作进程锁状态。
- `worker-<id>.log`：权限受限的后台任务启动错误日志，供主机排查启动失败；不直接作为接口响应返回。
- `worker-<id>.mjs`：接收任务时保存的工作进程源码快照，独立于待替换的插件包；工作目录固定为 profile 根，避免更新进程占用旧包。
- `transaction-<id>.mjs` 与 `market-<id>.mjs`：同一任务使用的模块快照，避免 Remote 自更新替换自身包目录后影响正在执行的任务。
- `recovered-lock-<id>.json`：人工恢复时保留的旧锁记录。

失败不会声称已回滚：包管理器可能已改变依赖，旧版任务的备份仅覆盖配置文件。已知工作进程和 CLI 均退出后，状态查询或下次提交标记任务中断并自动解除锁，任一进程存活则保留锁。旧版本缺少进程记录的锁提供“恢复旧任务”：需先在主机确认安装进程已退出，再明确确认解除；服务端校验锁 id、配置 revision 和确认字段，并保留旧锁备份。不能通过超时推断安装已结束。操作记录不会自动清理。

启用预检的新任务会在安装前备份完整插件树和控制文件，失败后可手动确认恢复，详见 [事务说明](plugin-update-transaction.md)。同一 profile 的 `local-plugins` 目录链接也会独立保存源码快照，并保留链接关系。若本地源码在失败期间或之后改变，自动恢复停止以保护用户源码；可在主机核对该任务的 `local-plugins` 副本。任意其他外部目录、嵌套越界链接仍会阻止安装。

## 验收

### 适配诊断与任务看板（未发布）

已适配条目增加运行、接口读取与待重启诊断，并链接排障知识库。列表不会自动查询费用、技能内容或任务快照。新增任务看板只读入口，读取当前已注册工作区的任务、执行结果、验收和计划，跳转可用执行会话；不提供任务写操作。费用和团队展示也已补全，详见[适配与验证说明](plugin-adaptation-2026-10-23.md)。

### 旧网关接管与远程自更新（未发布修复）

早期 0.7.x 的精简探活只在 `liveness.pid` 提供 PID。当前源码已兼容该结构，避免把仍运行的旧网关误报成普通端口占用；升级接管仍须通过原令牌认证关闭，不按公开 PID 强杀进程。

隔离测试实际运行插件、网关和独立 worker，覆盖宿主退出期间换包、宿主重启后新网关 PID/版本生效、原配对恢复、同任务重试幂等，以及换包后失败的明确恢复。另有本地 registry + 真实 pnpm 自更新验证。范围、证据与仍需主机验收的边界见[自更新验证记录](remote-self-update-verification.md)。

### Windows 自更新目录锁（0.8.0-rc.2）

旧插件曾以 `node_modules/dsh-remote-plugin` 为网关的当前工作目录。Windows 锁定进程工作目录，pnpm 将临时包重命名至正式目录时可能报 `ERR_PNPM_EPERM ... rename`。新启动的网关/监督进程改在 `~/.dsh-remote` 运行，更新任务改在 profile 的独立快照运行。测试在 Windows 上重现了当前工作目录锁，并在真实插件启动网关且 HTTP/WS 就绪时成功重命名整个隔离插件目录；自更新测试使用实际目录替换，不再只修改原目录内文件。

此修复不能改变已经运行的旧进程工作目录。受影响设备需要先保存日志和备份，退出对应 DSH Desktop 及其 Remote 网关，再使用该 Desktop 安装自带的 CLI 在原 profile 重新安装明确版本，随后启动 DSH。不能把 peer dependency 警告当作这次退出的原因，也不能把失败视为完整回滚；不要删除用户配置或通过反复重试、强制覆盖绕过目录锁。其他软件、ACL 或防病毒扫描仍可能造成 EPERM；没有检查报告设备的实际占用进程。

`npm run check` 包含参数注入拒绝、未知 profile 只读、鉴权、版本冲突、幂等、互斥、停用保留、失败记录、配置备份及真实独立工作进程测试。

设置 `DSH_TEST_CLI_ROOT` 为安装的 DSH 包目录后，`node --test tests/installed-dsh.test.js` 会在临时 HOME 启动真实 DSH，验证网关到插件中心的 profile 和运行状态链路。

设置 `DSH_TEST_DESKTOP_EXE` 为桌面程序、`DSH_TEST_DESKTOP_CLI` 为同一安装中的 `dsh-desktop-host/lib/cli.js` 后，`tests/desktop-plugin-center.test.js` 在临时 HOME/profile 验证真实 ASAR 入口、Electron 独立工作进程，以及安装 → 停用 → 更新（保持停用）→ 启用 → 卸载。全程固定版本、禁用安装脚本，不调用模型。卸载使用 pnpm 11 支持的 `--config.ignore-scripts=true`，安装和更新仍使用 `--ignore-scripts`。

本地 APK 构建需要 Android SDK 和现代 JDK。没有生成新 APK 前保留原 `public/update.json`，不把已有 APK 标成 RC。`npm run build-app` 成功后再运行 `npm run publish` 生成与新 APK 匹配的更新元数据。
