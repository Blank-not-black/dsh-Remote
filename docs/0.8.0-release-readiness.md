## issue #22：CRLF 会话渲染卡死

新报告已在热修前的本地 0.8.0 复现：CRLF 标题、引用和单行尾部 CR 会让 Markdown 段落分支不前进，缓存恢复也会反复触发。当前修复在 `public/md.js` 入口把 CRLF／CR 统一成 LF，未被块解析器接受的行则保留为转义文本并推进索引。没有清理、改写或要求用户删除历史缓存。

`tests/md.test.js` 新增三组带 VM 同步超时保护的回归，覆盖换行矩阵、末尾 CR、Unicode 行分隔符和文本保留。旧代码三组均超时失败；新代码通过。全量 `npm run check` 在允许 Windows 进程身份查询的环境为 978 项、959 通过、19 跳过、0 失败；首次沙箱运行的两项旧 supervisor 身份查询失败日志也保留。

独立 Chromium 页面从 localStorage 恢复并重复渲染 512 条合成消息，正常返回、保持响应，危险 HTML 仍为文本。这不是原报告者 Android 会话的真机复验。

本地 APK 重新构建成功，`versionName=0.8.0`、`versionCode=8010`；`npm run publish` 仅执行仓库定义的本地产物准备，没有运行 npm 对外发布。APK 的 md／genui／chat-files／build／version 资源与源码、插件副本一致，tgz 的渲染器、build.json 和内置 APK 也已核对。新产物与日志见 `dist/issue22-hotfix-2026-10-24/REPORT.md`。

issue 保持开启；尚未将此热修安装到 Windows／Linux profile、完成 Android 真机验收或发布。正式发布前须使用新候选包重新验证原卡死场景及缓存恢复，不能沿用旧 APK 的通过记录。

随后补充 7 组预防性测试：1,008 组标记／空白／换行组合、256 份固定种子文档、312 个流式前缀、深层／长文本、浏览器与插件加载方式，以及真实缓存 API＋HistoryView 的 420 条历史翻页／重开。扩展后专项 63/63、全量 985 项（966 通过、19 跳过、0 失败）；内存撤除两处修复也均被测试检出。见[回归覆盖与复跑入口](markdown-regression-coverage.md)。这一轮仅改测试和文档，没有重建或替换热修产物。

## issue #18 的正式版说明

可用于正式版已知问题说明的文案：

> 部分旧 DSH 会话可能因上游格式迁移器不识别 `fallback`、`instruction-hint` 等来源而无法读取。Remote 已隔离可识别的单会话观察失败，并显示迁移说明及历史重试入口；其他正常会话可继续使用。Remote 不修改原始会话日志，也不修复 DSH 的迁移器。请先在 DSH 中检查原会话并按上游提供的升级或迁移方案处理；若仍失败，请保留原始数据并提供脱敏诊断。此类旧会话的完整恢复仍待上游处理。

不要建议把 `fallback` 改为 `user`，不要自动重写日志、激活冷会话或反复重试迁移。遇到不属于单会话的全局连接故障，仍按连接错误处理，不能假装其他会话在线。

## issue #21 新反馈：旧网关升级接管

报告者已确认 rc.9 的冷会话按需观察修复有效，同时发现早期 0.7.x 精简探活缺少顶层 PID/上游/事件字段，导致新版插件将旧网关判为未运行，只提示端口占用。当前工作区已兼容 `liveness.pid`，仍只通过原令牌认证关闭旧网关。

远程自更新已增加宿主退出、真实包目录替换、重启后运行版本/PID 生效、认证失败拒绝接管、原配对继续使用及失败后明确恢复的隔离测试，并补充本地 registry 的真实 pnpm 自更新测试。详见[验证记录](remote-self-update-verification.md)。源码与模拟通过后，仍需候选包在实际主机验证；尚未公开发布或回访确认，不提前关闭 #21。
