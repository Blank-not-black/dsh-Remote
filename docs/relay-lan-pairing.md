# 局域网自动配置公网配对

Android App 与电脑 Remote 均更新后，手机先通过自己的电脑局域网地址连接并完成认证。主机已开启加密中转时，App 会提示确认局域网电脑和公网地址；确认后为这台手机创建独立配对，保存到 App 私有配置，并通过配对通道验证公网主机身份。成功后将公网地址添加到当前主机分组，保留原局域网地址和当前连接。无需保存、传输或手动导入 JSON 文件。

首次信任以用户确认的局域网连接为依据。请在自己信任的局域网内完成，不要确认来源不明的主机。主机证书变化会再次提示，不能静默覆盖旧证书。手动文件导入继续保留。

暂时没有出现提示时，可在“更多 → 主机与连接 → 云服务器中转 → 通过当前局域网连接自动配对”重试。电脑尚未开通中转时应先在电脑完成开通。旧版电脑没有此接口，需要升级电脑插件或独立网关；只升级手机无法补齐接口。普通浏览器不支持 App 原生加密通道。

每台手机使用独立凭据，最长有效 30 天，且不超过主机中转授权和证书有效期；设备列表仍可从电脑本地管理页查看、撤销。到期后连接局域网重新确认配对。已手动关闭该主机加密的选择保持原样，不会被重新导入覆盖。

`POST /relay/pair`（管理前缀下也支持）仅接收直接本地网络连接和有效 Bearer 凭据，核对当前证书指纹，只允许创建当前手机配对。它不开放设备管理、证书轮换或主机私钥。公网中转连接由实际 TCP 来源追踪拒绝，伪造 Host、转发头和请求参数不能绕过；响应禁止缓存。普通 `/relay` 状态接口不返回配对秘密。

创建请求不自动重试。保存或公网验证失败时保留局域网连接，不自动关闭加密，不自动重发用户任务；显式重试会优先复用已保存且有效的配对，避免重复创建设备。结果未知的创建可能留下一个未使用设备，可在电脑本地设备列表撤销。

## 状态与配对日志

设置页会逐步显示：读取局域网主机、确认、创建并保存配对、等待主机公网通道就绪（最长约 90 秒）、校验公网主机身份、成功或失败原因；失败会带错误码。创建设备会让主机中转客户端重连，首次配对等待期间不要重复点击；排队等待期间不会创建第二个设备。若通道仍未就绪，重试会复用已保存配对，不会重复创建设备。

“端到端加密配对（试验）”区域提供“配对日志（可复制反馈）”，保存在本机 App 存储中，可展开、复制、刷新或清空；日志不含访问令牌、设备密钥或路由凭据。主机侧同时写入 `~/.dsh-remote/pairing.log`（JSONL，单文件约 512KB 后轮转为 `.1`），只记录配对请求的结果、来源、设备 ID 和错误码，不记录秘密；反馈时可一并提供。可用 `DSH_REMOTE_PAIR_LOG` 覆盖主机日志路径。

公网旧入口仍会返回 `426 E2EE_TRANSPORT_REQUIRED`。它不影响局域网直连；应先完成上述配对，再使用自动添加的公网地址。
