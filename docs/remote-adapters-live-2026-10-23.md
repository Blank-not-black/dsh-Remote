## 真实服务与受控验收样例

未调用模型或执行计划任务。样例通过已安装插件的正式接口或发布包存储函数建立，并由真实运行的插件提供给 Remote，未替换 HTTP 响应或注入浏览器状态。

- **任务看板**：使用正式 Host `/api/task-board/action` 创建 3 张带验收标识的卡片；分别覆盖无执行记录、模拟外部失败报告、模拟外部成功报告及归档。外部报告标注为验收模拟，不能当成真实模型执行记录。
- **团队**：使用发布包 `createTeamDir` / `readTeam` 存储函数建立一个 `staged`、`awaiting_review` 的受控样例，包含 1 名尚未启动的成员、2 个待执行任务及一条依赖。队长为新建的空 DSH 会话。没有批准计划、启动成员或提交提示词。

## 2026-10-24 补验

团队、任务看板、扩展入口及发布包账本的相关回归共 **22 项，22 通过、0 失败、0 跳过**，日志为 `adapter-regression-isolated.log`。

首次补跑直接从已安装 `node_modules` 导入发布包 TypeScript，被 Node 的 `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING` 限制阻断，结果是 21 通过、1 失败；保留原日志 `adapter-regression.log`。随后将该包的 `src/` 和 `package.json` 原样复制到验收目录，通过 Node 内置 TypeScript 转换在临时 HOME 中运行账本契约检查。94 个文件与已安装包逐字节一致，摘要保存在 `published-source-verification.json`；没有修改发布包源文件或安装额外依赖。账本的模拟执行、结算和定时字段检查全部发生在临时目录，不运行真实模型或 Host 调度器。

补验后再次检查实际主机：团队 `0.1.26`、任务看板 `0.4.8` 和 Remote `0.8.0` 均启用且运行，两个适配接口可读，`pendingRestart=false`；上游、mux、host 正常。原有依赖与 Cordis 文件保持，样例已按文中说明归档和留存。
