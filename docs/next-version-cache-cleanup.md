# 下一版本：旧缓存迁移与容量管理

状态：待实现、待验收；当前已发布的 0.8.1 不包含自动清理。本项与公告保存失败的兜底修复一起安排到下一版本，不因本次公告重新开放而发布客户端版本。

2026-10-28 发布范围核查：0.8.2 候选源码已包含公告写入核验与会话存储／内存兜底、旧缓存占用诊断，尚未实现本文件所述的自动迁移、跨连接总量管理及自动回收。公告状态兜底不能代替清理旧缓存；正式版说明不得把本计划标为已完成。全量持久存储均不可用时，进程内状态仍会在结束 App 后丢失。

## 已确认的问题

2026-10-26 的 Android 0.8.1 现场检查发现，旧格式 `historyCacheV1` 和 `historyCacheV2:<连接哈希>` 整块缓存长期驻留 localStorage，占用了大部分配额。IndexedDB 可正常使用，但旧缓存没有统一迁移与回收；新公告历史、已读和填写状态因此可能无法写入。原版 APK 的 Android 模拟器测试也复现了存储满时的相同行为。

## 下版实现范围

- 识别两种旧格式，区分新格式的 `:session:` 记录和 `:cache-index`，避免误删。
- 设计可恢复的迁移与回收流程：迁移数据须确认事务提交后才清理旧副本；迁移失败不得将未保存的数据视为已完成迁移。无连接身份的 V1 数据不得混入其他主机的会话缓存。
- 对可重建的会话缓存实行跨连接的总量控制，回收长期不用的缓存，为连接配置、公告已读及填写标记保留空间。
- 纳入公告写入核验及会话存储／内存兜底修复，诊断日志只记录缓存类别、数量和失败阶段，不包含正文或凭据。
- 保留手动「清除历史缓存」入口，清理本机缓存时保留主机记录和连接配置。

## 验收要求

- 在 Android 模拟器中保留原版 App 的旧格式缓存，覆盖升级后自动回收、迁移失败和多连接累积场景。
- 清理后新公告能进入历史；确认已读、刷新、切后台和重启后不重复弹出；成功提交后能保存填写标记。
- 验证连接凭据、其他设置及主机对话记录不变；新旧连接的历史不能串用。
- 运行对应回归测试及全量 `npm run check`，构建 RC 并完成真机验收后再发布。
