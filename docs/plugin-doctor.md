# AI 排查插件问题

DSH Remote 在插件首页的“添加手机”旁、控制台顶部和“连接诊断”页提供 **AI 排查问题**，App 首页的主机连接卡下方也提供直接入口。它用用户自己的 DSH 和当前模型，在独立会话里按证据做只读诊断，并整理反馈草稿；不代替用户提交公开 Issue。

## 使用流程

1. 点击“AI 排查问题”。打开面板只读取诊断目标，不创建会话、不调用模型。默认目标是主机实际加载的 Remote 插件目录，面板显示路径和技能注册状态；也可以选择主机已有的源码工作区。不会把插件依赖目录自动添加为工作区。
2. 阅读额度与隐私提示：开始后会新建独立诊断会话，并使用该会话配置的模型（通常是 DSH 默认模型），消耗对应额度或产生费用；脱敏诊断信息会发送给该模型服务。
3. 描述问题现象。可选附带本机脱敏操作日志。日志只包含操作阶段、耗时、错误位置和连接状态，不含令牌、Cookie、对话正文或完整路径。
4. 选择“开始只读诊断”。Remote 会在所选目录或工作区创建独立会话，并发送带 `dsh-remote-doctor` 技能标记的排查请求。插件抽屉通过主机打开该会话；独立网关管理页切换到 Remote 会话页面。单独打开的宿主网页会返回 DSH 首页，可在最近会话中找到诊断会话。
5. 查看诊断结论。诊断会话必须区分已确认异常、可能原因和仍需验证项，并在最后给出可选 Markdown 反馈草稿。
6. 用户自行决定是否反馈：
   - 复制诊断会话里的反馈草稿，粘贴到“写反馈”或 Issue。
   - 在“AI 排查问题”面板复制反馈模板，补充复现步骤和结论。
   - 打开预填的 GitHub Issue 页面，检查并手动提交。

提示词发送前关闭或取消面板，会停止后续发送；若独立会话已经创建，可能留下一条空会话。提示词已经发送后，关闭面板不会撤回请求，需要在诊断会话中停止运行。

## 诊断边界

- 默认只读。检查版本、回环 `/health`、进程状态和有限日志尾部；不自动改配置、重启、升级、删除或提交反馈。
- 分别核对源码、实际安装包与运行进程；源码目录里的版本不能代替实装和运行证据。
- 需要写入或重启的下一步会标为“需你确认”。
- 不读取或输出 token、Cookie、凭据、对话正文、上传文件和完整个人路径。
- 只访问本机回环健康端点，不探测第三方提供的 URL。
- 工具审批被拒绝时记录为证据缺失，不绕过审批。

## 断线兜底

- DSH 或 Remote 不可连接时，入口仍可打开。
- 可以复制通用排查提示词、复制或导出本机脱敏诊断、复制反馈模板，或打开 GitHub Issue 手动反馈。
- 新会话创建成功但发送失败时，Remote 会打开该会话，并尽量把排查提示词复制到剪贴板，用户可手动粘贴发送。
- 会话页面确认打开后，诊断面板才会关闭。打开失败时，面板保留错误和“打开诊断会话”按钮；点击该按钮只重试打开已有会话，不再次创建会话或发送诊断请求。面板会区分创建会话、发送请求和打开会话三个阶段。

## 内置技能与兼容性

- 随包知识库位于 `skills/dsh-remote-doctor/references/wiki/`，与仓库 [操作与排障知识库](wiki/README.md) 同源；Doctor 按症状读取相关条目并引用 KB 编号。用户自己的 AI 可从根 `llms.txt` 或 [AI 指引](wiki/ai-guide.md) 开始。文档说明操作方法，不自动授权 Doctor 写入或重启。

- 插件包随附 `skills/dsh-remote-doctor/SKILL.md`，在宿主提供技能注册表时以 `bundled` 来源注册为 `dsh-remote-doctor`。
- 旧版 DSH 没有技能注册表时，插件仍可加载；前端提示词本身包含完整的只读排查边界与输出要求，因此诊断会话仍可运行。
- 诊断能力依赖当前模型、工具权限、主机日志和网络状况。它是证据整理助手，不是确定性的故障判定器，也不保证根因。
- 反馈草稿和预填 Issue 都需要用户审阅；公开提交是用户独立操作。
