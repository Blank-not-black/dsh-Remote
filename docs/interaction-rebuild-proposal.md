# DSH Remote 操作逻辑重构提案

日期：2026-10-15。状态：待用户挑选的完整提案，尚未实施。

本提案根据当前工作区源码、现行文档以及用户反馈制定。用户原话：“之前一直是增量更新，有些常用功能的操作有时过于复杂，有些赘余内容可以合并或者删除。”用户选择先看完整方案，再决定取舍。

本文中的新页面、新流程和操作步数均为建议及验收目标，不代表已经实现或测量。频率排序是基于产品用途的判断，目前没有用户行为统计。旧《四端产品与 UI 低保真蓝图》保留作历史参考；本提案尚未取代现行规则。

## 1. 推荐结论与可独立选择的决策

重构围绕四项用户任务展开：找到正在做的工作、继续发指令、处理需要自己决定的事情、取得文件结果。连接与主机维护为这些任务提供支持。

| 决策 | 推荐方案 | 用户可选的保守方案 | 代价与边界 |
| --- | --- | --- | --- |
| D1 主导航 | 手机收敛为“会话 / 文件 / 更多”，主页内容并入会话起始页；待办按需置顶 | 保留五导航，先精简主页 | 推荐方案减少入口选择，但移除独立主页，需要迁移入口提示；插件多一次进入 |
| D2 工作组织 | 用户只需理解“主机 → 工作区 → 会话”；现有工作台目录绑定降为高级组织配置 | 保留工作台名称，默认折叠 | 统一概念需要映射旧数据，不能直接删除工作台后端能力 |
| D3 发送方式 | 默认排队；繁忙时显式提供“排队发送 / 插队发送”；长按降为可选快捷手势 | 保留默认方式设置，同时加可见选项 | 推荐方案改变繁忙发送习惯，需显式迁移旧偏好 |
| D4 插件位置 | “更多 → 主机插件”，直接打开已安装列表，专属入口仍属于相应插件 | 保留底部“插件” | 偶尔维护用户获益；经常管理插件的用户多一次进入 |
| D5 主机管理 | 所有客户端只保留一个“主机与连接”入口；深度设备/端口/诊断进入现有管理控制台 | 保留关于页中的启动与重启按钮 | 统一入口，但启动/重启涉及能力校验，不能仅搬按钮 |
| D6 技术信息 | 常态只显示“已连接 / 正在恢复 / 需重新登录”等用户状态；详情展开 | 保留四链路显示，默认折叠 | 排障人员多一次展开，原始诊断数据继续可查 |
| D7 通知设置 | 先选择提醒类型；后台能力与权限跟随引导，间隔放高级项 | 维持现有全部开关 | 推荐方案需解释前台提醒与后台接收的区别 |
| D8 历史与结果 | 以会话为中心，保留历史阅读保护，文件卡片直接预览/下载 | 只整理现有菜单 | 聊天文件预览属于增强项，需文件类型及路径能力检查 |

建议先选择 D2、D3、D5、D6；它们直接改善操作。D1、D4 可独立选择，不把“砍导航”作为其他改进的前提。

## 2. 当前结构中的具体问题

### 2.1 已确认的界面与流程事实

| 问题 | 当前证据 | 对操作的影响 |
| --- | --- | --- |
| 组织概念并排 | 手机会话页同时有工作台栏、工作区选择器、路径、排序及两个创建按钮 | 用户需要判断当前在哪个层级、应点哪个创建入口 |
| 新建会话重复选择 | `newSession()` 每次打开工作区确认弹窗，即使列表已有确定工作区 | 经常在同一目录工作仍需额外确认 |
| 输入菜单混合用途 | “＋”展开命令、预设、模型与思考档位，图片另有入口 | 插入内容、改变会话设置、执行管理动作混在一起 |
| 插队依赖记忆 | 需要开启长按设置，并理解短按/长按随默认方式互换 | 不易发现，存在发成另一种模式的风险 |
| 高频流程被支持入口挤占 | 手机顶栏持续显示赞赏、反馈、刷新和连接徽章 | 用户工作时反复看到低频内容 |
| 总览与会话信息重叠 | 独立主页提供近期会话、待办和状态，会话列表也提供工作摘要 | 多个入口可达同一任务，信息层级分散 |
| 命令按钮仍需发送 | 点击 `/compact` 等快捷项通常只填入输入框，用户还需发送 | “执行动作”和“插入文字”的反馈不一致 |
| 维护入口分散 | 关于页放 DSH 探测/启动/重启；另有完整管理控制台 | 用户难判断故障应去哪一页处理 |
| 空测试入口 | Android/Web 功能测试子页保留导航，ASR 功能已移除 | 进入后缺少实际可完成的任务 |
| 重置范围不清楚 | 文案称清空本地数据；当前处理只删除列出的部分 key，服务器集合另行持久化 | 必须先定义清除范围，避免用户误以为已退出全部连接 |

这些是源码走查结论，不等于每位用户都遇到，也没有虚构完成率或平均耗时。

### 2.2 交互诊断

使用 design-everyday-things 的五项尺度做静态工程判断：0=缺少，1=部分明确，2=明确。当前 6/10，仅用于定位问题。

| 项目 | 当前 | 主要缺口 | 方案验收方向 |
| --- | --- | --- | --- |
| 找得到操作 | 1 | 插队依赖手势，命令和设置混放 | 常用动作有可见名称 |
| 理解结果 | 1 | 命令插入与执行不同；发送成功、接收成功与任务完成易混淆 | 每种动作反馈作用阶段 |
| 错误后恢复 | 1 | 重置含义含糊，网络失败缺少统一恢复路径 | 保留输入，提示下一步，清除范围可解释 |
| 控件与对象对应 | 1 | 主机/工作台/工作区入口分散 | 操作旁清楚标出主机、目录或会话 |
| 不可用操作约束 | 2 | 已有插件运行能力、连接隔离和管理只读约束 | 重构保留并统一呈现 |

目标是修复前四项，再通过真实任务走查验证；不以视觉改版自评满分。

## 3. 统一概念与新信息结构

### 3.1 三个工作对象

- 主机：我正在远程操作哪一台 DSH。它有一个或多个连接地址。
- 工作区：这台主机上的哪一个工作目录。
- 会话：在该目录中正在进行的某项工作。

“工作台”保留为高级目录组织能力，普通用户无需先绑定工作台才能查看已有会话或开始工作。“服务器组”可以继续作为地址管理中的高级组织方式；不直接把所有旧组自动重命名成主机。

### 3.2 手机推荐导航

```text
顶栏：当前主机与连接状态 → 切换 / 管理连接
│
├─ 会话（默认进入）
│  ├─ 有待办时：待审批 / 待回答，按会话组织
│  ├─ 工作区选择 + 新会话
│  ├─ 运行中与最近会话
│  └─ 已归档（折叠）
├─ 文件
│  ├─ 当前工作区目录 / 授权根
│  ├─ 预览与下载
│  └─ 上传及传输进度
└─ 更多
   ├─ 主机与连接
   ├─ 主机插件
   ├─ 模型与提供方
   ├─ 通知与后台
   ├─ 外观与输入
   └─ 关于与维护：更新 / 公告 / 反馈 / 本地数据
```

待办属于会话页的条件区域，也可展开成完整待办视图；无需新增第四个常驻导航。没有待办时不占据大块空状态。主机离线时显示一个恢复条，并保留缓存列表；技术详情按需展开。

### 3.3 会话内部

```text
顶部：返回 | 会话标题、主机和工作区摘要 | 更多
任务区：有审批/问题时显示；目标与子代理按需展开
正文：对话、思考、工具结果、文件卡片
输入区：附件 | 文本输入 | 发送（繁忙时标明排队发送）| 发送方式
会话配置：当前模型、思考档位及模式的紧凑入口
```

会话中的主机摘要在单行内展示；完整地址、目录和 ID 在详情展开。切换主机或会话不自动发送草稿，不把旧草稿带给新对象。

## 4. 高频任务的重新设计

### F1 打开后继续工作

当前：会话页与主页分别提供列表和近期工作。

建议：默认会话起始页显示运行中和最近会话，点一次进入；从后台恢复仍保留原页面与阅读位置。需要审批/回答时显示待办提示，用户主动进入。深链通知可直接进入所属会话，不重定向到总览。

目标：应用就绪的列表页进入最近会话只需 1 次点击。启动、认证和网络等待不计作点击，但单独检查。

### F2 在当前目录创建会话

当前：点新会话，再进入工作区确认弹窗。

建议：工作区已明确时，点新会话直接创建，空会话首屏清楚标出目录并允许更换。在“全部工作区”视图下，新会话先显示目录选择；只有一个工作区时自动采用并显示名称。更换目录必须在发送前完成，不移动已开始执行的任务。

没有工作区时，同一流程提供“选择已有目录 / 新建目录”。后者才创建文件夹。选择已有目录是否能登记需确认上游能力，不允许靠猜路径绕过授权。

目标：确定工作区时 1 次点击创建；需选择工作区时最多 2 次点击完成，不计文字输入和系统目录选择器内部操作。

### F3 发消息、排队、插队和停止

建议：空闲时“发送”；繁忙时主动作明确显示“排队发送”，旁边可见的方式菜单提供“插队发送”。长按可作为可选捷径，但所有动作都有点击路径，键盘提交遵守屏幕上明确显示的方式。

排队列表继续支持将某一条插队；仅在运行条件满足时可用。“停止本轮”保留独立按钮，不与发送复用成含义变化的图标。“暂停目标”放在目标卡片中。

发送反馈统一为：提交中 → 已接收/已排队，或明确拒绝，或结果未确认。结果未确认时保留原始内容并引导核对，不自动重复提交。目标完成和模型回复完成使用各自的执行状态。

旧版自定义默认插队的用户，迁移后首次繁忙发送前必须看见新的明确方式；不能让旧偏好静默改变行为。

### F4 处理审批和回答

会话起始页提供待办摘要和完整列表，按主机内的会话归属组织。审批在摘要中显示足够的工具/目标信息，详情能展开；允许或拒绝后反馈对应请求结果。问题始终进入完整弹窗，单选、多选及文字按请求契约展示，不为了减一步丢失题干。

会话内部保留同一请求的上下文入口。两处使用同一状态与提交逻辑，处理后同步消失。取消弹窗只表示稍后处理，不提交默认答案。

目标：从起始页找到待办 0 次额外跳转；已展示完整审批信息的条目可以 1 次操作处理；回答仍需明确提交。

### F5 获取任务文件

聊天文件卡片提供“下载”；支持预览且路径可解析时提供“预览”。相对路径按原会话目录解释。未提供路径或附件接口不可用时给出具体原因和可行下一步，不宣称已下载。

会话详情中的“查看文件”定位所属工作区；从文件页返回后恢复原会话、阅读位置和未发送内容。独立文件页继续用于跨目录浏览与批量任务准备，不扩建完整 IDE。

目标：卡片下载 1 次点击；从会话打开所属目录不超过 2 次点击。系统保存位置选择另计。

### F6 切换模型与思考档位

模型和思考档位从“＋”迁到可见的会话配置入口，打开一个面板即可选择。模型、思考档位、计划模式、权限预设属于不同设置，分组展示。后两项仅在主机能力与当前状态可确认时给出明确控件；否则继续使用命令，不能自行猜测 RPC。

提供方和密钥编辑仍进入“更多 → 模型与提供方”，不挤入每次聊天的模型选择器。打开主机配置文件的操作改成“在主机打开配置文件”，避免让手机用户误认为能在当前设备编辑。

### F7 网络断开后恢复

显示“正在重新连接”等用户结论，保留历史缓存和草稿；等待自动恢复，也提供手动重试。展开后才显示地址及 mux/host 等技术信息。

网关在线但 DSH 离线时，引导进入主机状态；后端支持受控启动时显示“启动 DSH”。网关也不可达时，引导检查网络或在主机端启动，不能显示一个无法送达的远程启动操作。

### F8 插件与专属页面

“更多 → 主机插件”进入已安装列表。搜索、详情、启停、更新、卸载继续在插件上下文内操作。安装后集中提示需要重启；重启由用户明确触发，不能安装完成后擅自中断正在运行的会话。

技能、费用入口仍只出现在对应可用插件中；当前会话可按能力显示上下文和费用入口。无插件、停用、失败或未知状态不显示推介卡片。列表/详情返回继续保持位置。

## 5. 全量功能处置表

“删除”分为删除入口、删除设置或删除客户端功能。下面没有任何删除主机用户数据或自动卸载插件的建议。

| 范围 | 现有操作/内容 | 建议处置 | 目标位置与逻辑 |
| --- | --- | --- | --- |
| 接入 | Web/Desktop 插件安装、独立网关、APK、鸿蒙签名安装 | 保留 | 入门文档按实际平台分流，不合并成一种安装假象 |
| 连接 | 扫码、相册导入、手填地址/令牌 | 合并入口 | 添加主机流程内提供三种方式 |
| 连接 | 多地址、备注、编辑、删除 | 合并展示 | 主机连接详情中管理；底层仍区分地址与凭证 |
| 连接 | 分组增删改 | 降级 | 高级组织，不强迫首次连接建组 |
| 连接 | 测速、自动选优、手动指定 | 合并 | 连接详情中“自动连接 / 固定地址”；保留显式测速 |
| 连接 | 顶栏组选择、设置服务器列表 | 合并实现 | 顶栏快速切换，管理页负责编辑，两者共用数据 |
| 连接 | 单独访问令牌按钮 | 合并入口 | 当前主机连接详情中管理凭证，不留全局含糊令牌 |
| 连接 | 正常/弱网/自动 | 降级 | 自动为默认；高级连接项保留手动覆盖 |
| 连接 | 自动重连、轮询回退 | 保留 | 自动处理；详情解释当前模式 |
| 起始页 | 独立主页 | 合并页面 | 近期会话、待办并入会话；主机状态进入连接条 |
| 起始页 | 4/4 链路、版本、协议等常驻指标 | 降级 | 连接详情与诊断；异常只展示可执行结论 |
| 起始页 | 公告、投票大区域 | 降级 | 关于中的公告列表；未读时提供低干扰提示 |
| 起始页 | 最近工作、运行中会话 | 合并 | 一个会话列表中按状态和时间组织 |
| 起始页 | 顶栏反馈、赞赏 | 删除常驻入口 | 功能保留于关于与反馈 |
| 起始页 | 顶栏全局刷新 | 合并刷新逻辑 | 自动刷新为主；当前列表保留显式刷新，触摸端可有下拉手势 |
| 工作区 | 工作台绑定、项目根目录 | 降级 | 工作区管理的高级目录组织；保留旧绑定能力 |
| 工作区 | 两套工作区/工作台展示 | 合并概念 | 普通列表以工作区统一组织，保留来源信息 |
| 工作区 | 已知目录下的新会话确认弹窗 | 删除重复步骤 | 直接创建并显示目标目录 |
| 工作区 | 新建工作区 | 重做流程 | 在创建入口选择已有目录或新建目录，按上游能力登记 |
| 工作区 | 排序、拖动重排 | 保留并降级设置 | 默认最近活动；高级排序与整理时才显示重排提示 |
| 会话 | 标题、目录、ID、复制路径 | 合并 | 标题打开详情，常驻只显示短摘要 |
| 会话 | 重命名、归档 | 保留 | 会话更多菜单；归档显示影响并确认 |
| 会话 | 查看已归档 | 保留 | 列表折叠区域；不宣称具备恢复或永久删除接口 |
| 会话 | 空会话自动归档 | 保留 | 继续检查草稿、内容、执行和队列，不误收起有效工作 |
| 输入 | 文本、图片、移除图片 | 保留 | 附件与输入区；相机/相册按平台能力呈现 |
| 输入 | 全屏输入 | 保留 | 长内容按需展开，恢复草稿 |
| 输入 | “＋”混合命令/预设/模型 | 拆分职责 | 附件负责加内容；模型归会话配置；命令归操作菜单和斜杠输入 |
| 输入 | 提示词预设增删改和插入 | 保留 | 输入工具中选择；维护放外观与输入 |
| 输入 | 排队与队列条目插队 | 保留 | 主输入区与队列，动作有明确名称 |

## 6. 明确建议删除的东西

1. 独立主页这一重复层级（取决于 D1 的选择），其中有用内容迁移。
2. 顶栏常驻赞赏与反馈按钮，功能归入关于。
3. Android/Web 的空功能测试导航入口；鸿蒙 ASR 诊断保留。
4. 已确定工作区时的重复新会话确认步骤。
5. 插队必须先到设置开启才能发现的门槛；长按可继续作为可选捷径。
6. “清空本地数据”这一范围含糊的单按钮，改成范围明确的数据管理。
7. 默认页面重复展示的链路、路径、版本与用量大块内容，详情可查。

暂不建议删除模型配置、插件管理、文件传输、历史缓存、目标控制或后台通知。它们的使用频率需要用户验证，现阶段先调整入口。

## 7. 多端职责

| 端 | 统一规则 | 具体呈现 |
| --- | --- | --- |
| 手机 Web/Android | 同一主机/工作区/会话模型、发送语义、待办与恢复逻辑 | 三主导航、局部弹层；Android 接系统通知/下载/安装 |
| 桌面 Web | 业务规则相同 | 左侧工作区/会话，中间工作内容，右侧按需详情；插件/设置收至侧栏更多区 |
| HarmonyOS | 对齐主要任务路径与命名 | 使用系统组件；未移植洞察、GenUI、Web 缓存不显示假入口；后台与权限单独验证 |
| DSH 插件面板 | 主机上的快速连接与管理入口 | 状态、启动/停止、配对和进入管理页；细节与统计下沉 |
| 网关管理控制台 | 设备与连接维护 | 运行状态 → 添加设备/访问管理 → 诊断 → 用量详情 |

手机精简导航不要求桌面把宽屏布局改成三张手机页面。所有端的相同动作必须保持对象、提交语义和成功反馈一致。

## 8. 操作反馈与恢复规则

| 状态/操作 | 应呈现 | 恢复方式 |
| --- | --- | --- |
| 无连接 | 连接主机入口，扫码/手填 | 不要求先配置组或工作台 |
| 网关不可达 | 当前网络/目标地址与重试 | 自动恢复 + 手动重试；保留草稿和缓存 |
| 网关在线、DSH 离线 | 主机离线结论 | 按后端能力显示启动或主机检查指引 |
| 凭证失效 | 当前主机需重新登录 | 更新凭证，不循环无效重试 |
| 实时降级 | 正在通过备用方式同步 | 可展开查看轮询模式，保持操作能力边界 |
| 消息提交超时 | 结果未确认 | 查看最新历史，避免自动重发 |
| 上传失败 | 失败原因及可恢复进度 | 按回执续传或重新选择，校验失败明确处理 |
| 创建目录成功、会话失败 | 分别显示已完成和未完成部分 | 能力允许时在已有目录重新创建，不重复 mkdir |
| 插件管理失败 | 已知阶段、日志及状态 | 查看任务、按安全契约恢复，不声称自动回滚 |
| 目标修订冲突 | 目标已变化 | 读取最新目标后继续，不覆盖别处更新 |
| 本地清理 | 将删除的本机范围 | 明确确认，保留主机数据 |

“返回”恢复进入前的对象、筛选、滚动位置与草稿。遮罩、系统返回键、Esc 和页面内返回都遵守同一层级。用户有未提交配置时提供保留/放弃路径；后台任务不因关闭面板被误标为已取消。

## 9. 数据迁移与不可破坏的边界

- 新主机展示可聚合备用地址，但地址+令牌仍是底层认证和缓存身份。旧组可能包含多台主机，不能直接自动归并；相同地址不同令牌不合并。
- 默认使用现有连接模型承接第一阶段 UI；真正引入主机对象前定义 schema、迁移映射和恢复方案，不仅按地址相似性判断同一主机。
- 保留旧服务器、分组、固定地址、主题、预设、排序、工作台绑定及缓存迁移记录。新 UI 可以隐藏旧概念，不能清空旧配置实现精简。
- 路由迁移要覆盖旧二维码、deep link、通知跳转与旧书签；旧主页/插件入口能定位到新位置。
- 旧发送偏好迁移须解释行为，处理所有点击、回车、全屏输入和手势入口。
- 清缓存不删除登录信息。移除当前连接要说明备用地址和对应凭证范围。清除全部配置要覆盖 Web 持久化存储及 Android 后台配置，停止相应任务，防止后台仍使用旧凭证。
- 密钥依旧使用 DSH 凭据接口；不进入本地历史、URL 或日志。
- 目标、审批、消息、文件和模型请求继续检查连接与会话归属；A→B→A 不能接受第一次 A 的旧响应。
- 不新增虚构的上游 RPC；实际不支持的目录登记、模式控件、归档恢复或文件编辑不作为首轮交付承诺。
- 文件授权根、上传校验、GenUI 沙箱、插件运行能力与管理保护继续遵守当前契约。
- 零新增运行依赖、单文件网关、零构建前端保持；根 public 为源码，同步按仓库流程执行。

## 10. 实施顺序与独立验收

阶段顺序按风险和用户收益排序，不用虚构 RICE 数据。可全选方向，但通过多个 RC 验证，便于定位失败和回退。

| 阶段 | 交付范围 | 可独立验收的结果 |
| --- | --- | --- |
| A 核心操作 | 工作区概念、新建会话、发送方式、模型入口、命令动作、会话文件入口 | 在现有导航里也能完成高频任务；不先做视觉大改 |
| B 页面组织 | 按用户选择执行 D1/D4；合并主页待办/近期会话；整理更多与连接入口 | 导航减少，已有功能逐项可追踪到新位置 |
| C 维护与迁移 | 通知引导、主机状态、明确数据清理、配对/设备流程与旧入口迁移 | 首次连接、离线恢复、换主机、清理和通知跳转不混淆 |
| D 多端收敛 | 桌面同步行为、Android 真机、鸿蒙对应流程 | 分别记录源码/构建/安装/真机证据，不用一端结果代替其他端 |

实施时改动不提交、不部署；按用户选择范围开发、同步、检查并构建 RC。APK/HAP 版本策略需在实际构建前按 docs/release.md 决定，不在提案阶段改版本。

## 11. 验收场景和目标

点击数从指定起点开始，不计键盘输入、系统权限与系统文件选择器内部动作；这些系统流程单独记录。现状步数只对明确源码路径计数，其他项需实际界面测量。

| 场景 | 起点与目标 | 必须保留的正确性 |
| --- | --- | --- |
| 继续最近工作 | 列表页 → 1 次点击打开最近会话 | 后台恢复不丢历史位置 |
| 已知工作区新会话 | 当前工作区列表 → 1 次点击创建 | 创建前可见目录，错误有反馈 |
| 选择工作区新会话 | 全部列表 → 不超过 2 次点击创建 | 不随机采用不明确的工作区 |
| 发送消息 | 已填输入框 → 1 次点击发送 | 显示主机/会话归属，不重复提交 |
| 繁忙时插队 | 输入完成 → 不超过 2 次点击 | 无需开启隐藏手势，反馈接收状态 |
| 审批 | 起始页待办 → 信息完整时 1 次决定 | 不隐去风险判断所需参数；与其他端去重 |
| 长问题回答 | 摘要 → 完整题目 → 提交 | 题干可滚动，底部提交可达 |
| 下载聊天文件 | 文件卡片 → 1 次点击开始下载 | 相对路径属于原会话；结果按平台真实反馈 |
| 查看会话目录 | 会话 → 不超过 2 次点击定位目录 | 返回恢复草稿和阅读位置 |
| 模型切换 | 会话 → 不超过 2 次点击选择模型 | 主机元数据、当前会话与思考档位正确 |
| 查看插件 | 起始页 → 不超过 2 次点击到插件列表 | 可选能力不变默认推荐 |
| 主机恢复 | 异常条 → 不超过 2 次点击到具体动作 | 只显示后端能完成的操作 |
| 读历史时持续更新 | 回看、展开、选择文字后继续更新 | 不抢滚动，回到最新才恢复跟随 |
| 快速切主机 | A→B→A 并交错慢请求 | 无旧会话、审批、文件或发送回执污染 |
| 清除本地配置 | 数据管理 → 范围明确的确认 | 删除目标存储并停止相关后台任务，主机数据不受影响 |

自动验证针对连接隔离、发送语义、路由恢复、主机能力、迁移和数据清理等关键边界；不为纯文案或位置移动堆砌镜像测试。最终需要 Android 物理设备与桌面浏览器完成真实任务走查，鸿蒙另列状态。

## 12. 待用户挑选的最小决策集

1. 导航选三入口，还是暂留五入口？推荐三入口，但可后做。
2. 是否统一工作区概念并隐藏日常工作台绑定？推荐统一。
3. 是否固定排队默认、显式插队、长按可选？推荐采用，迁移旧偏好。
4. 插件进入“更多”，还是保留主导航？推荐进入更多。
5. 是否接受明确删除的七类内容/步骤？可逐项选择。

其他部分可作为共同实施规则：阅读位置、输入、请求归属、可选插件边界和明确操作结果都要保留。

### 14.2 已有可复用基础

- 网关每个通道共享一条上游 collector，客户端不各自新增上游订阅连接。
- mux/host 独立长轮询，最长等待默认 25 秒，支持 since、truncated 和 WS 恢复；一个空闲通道不挡住另一通道的新审批。
- 历史弱网分页从 60 降至 20，客户端相应读取预算从 45 秒增至 90 秒；静态资源和大历史已有 gzip，静态资源有 ETag。
- 已有连接 generation、迟到回执隔离、部分并发读取合并、事件触发刷新合并和本地历史缓存。
- 上传已有 session、offset、probe、服务端回执、最终 SHA-256 校验、同名冲突和写入互斥。
- 插件安装已有主机任务、任务 ID、配置 revision、互斥与记录；DSH 启动/重启已有 operationId 和进度查询。
- 大部分已登记斜杠命令已有异步受理与 command-status，客户端离开不取消执行。

### 14.3 优先处理的六项

**B1 列表刷新移除串行目录发现和隐式写入。** `refreshSessions()` 后触发 `refreshWorkbench()`；后者依次读取 /workbench、workspace.list，绑定目录时再读 /fs/list，随后还可能逐个 workspace.create。将工作区读取独立缓存/合并并发请求；目录发现改为明确触发的整理操作，或由主机后台维护并公布结果。普通浏览与刷新不触发成批写入。示例：RTT 为 800ms 时，4 次串行往返仅网络耗时就约 3.2 秒，尚不含执行和传输。这是计算示例，非实测。

**B2 写入操作建立稳定身份和查询契约。** 当前通用 rpc 每次生成新的 rpcId；消息 payload 没有固定 requestId。新 DSH 适配路径在 requestId 缺失时由网关临时补 UUID，重新提交会得到另一个值；这不足以证明安全重发。需要一次用户意图固定一个 operation/request ID，查询同一结果，界面区分提交中、已接收、明确失败和结果未知。先核验各 DSH 版本的去重能力；旧 DSH 不支持时保持结果未知和人工核对，不自动重放。网关本地日志也不能单独解决“上游已执行、网关未记账即崩溃”的原子性缺口。

**B3 事件恢复增加网关实例标识。** 当前内存 eventNextSeq 在网关进程启动时从 1 开始；客户端靠 truncated 或 latestSeq 小于旧 since 识别重置。已用生产 eventPollPayload 函数模拟：旧 since=20，新进程已产生 1～50，响应从 21 开始、truncated=false、latestSeq=50，客户端不会触发重置，可能漏接新进程 1～20。应新增 streamEpoch/实例 ID，客户端发现变化就重取会话、待办、队列及当前历史。恢复待办需要可确认的权威快照或重放基线，不能仅靠 session.list；相关上游契约要核实。可追加字段并协商能力，旧客户端保持兼容。

**B4 对齐超时并改造同步导出。** 网关上游默认 30 秒，普通客户端 RPC 45 秒，弱网历史 90 秒；三者度量的链路不同，不能只延长前端。/export 仍同步等待：插件预算 120 秒、客户端 125 秒，但普通网关代理有默认 30 秒的上游空闲超时，长时间无响应时可能先断开。优先将导出统一为异步任务：短请求受理 → 状态查询 → 结果下载；明确任务归属和有效期。其他请求分别定义连接、上传、服务执行、响应读取和操作有效期，不统一设成一个超大值。

**B5 实时推送加入慢客户端背压。** 当前 broadcastCollectorFrame 对 socket.write 返回值和积压字节没有在该广播循环设置边界。持续流式输出加弱网可能积压内存和延迟状态。需要限定每设备缓存/积压，并在超限时使用明确的断开与恢复流程；合并临时思考增量前需验证语义，审批、终态和已持久化历史不能随意丢。当前仅是源码风险，没有测得真实 OOM。

**B6 文件上传增加弱网自适应与停滞反馈。** 当前客户端固定 4MiB 分块，XHR 没有显式 timeout/onTimeout。复用现有协议，按吞吐/RTT采用受限块大小和停滞检测；超时后先 probe 对齐服务端 offset，再续传，不盲目重发。更小块减少失败重传量，但高 RTT 下每块等待会降低吞吐，因此不固定一律用小块。默认保持单任务传输，避免占满连接影响审批。

### 14.4 新界面的请求约束

1. 首屏优先读取会话和待办，费用、技能、统计在用户打开时读取；慢插件不挡住聊天。
2. 共享连接、事件流和状态层；页面合并不增加轮询器，同一读取合并在途请求。
3. 页面跳转不自动重拉全部数据；先显示有效缓存，再后台更新，并标注新鲜度。
4. 消息和审批等控制请求优先；历史分页、诊断和文件任务有界并发，限制后台争抢。
5. 一次受理回执可以驱动局部状态，无需等待整个会话列表刷新才结束按钮加载；结果仍等待主机确认。
6. 模型切换成功后才将新消息归于新模型，不能让“切模型”和“发送”并发竞争。
7. 第一轮优先减少请求和串行依赖。确需网关摘要接口时再按身份隔离、标明缓存年龄及部分失败，不做包含插件、诊断和文件扫描的巨型首屏接口。
